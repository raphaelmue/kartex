# Requirements Archive: Kartex v1.0 MVP

**Archived:** 2026-05-30
**Status:** ✅ All v1 requirements shipped and verified

---

## v1 Requirements — All Complete

### Authentication (AUTH)

- [x] **AUTH-01**: User can register with a username and password using a valid invite code (no open sign-up)
- [x] **AUTH-02**: User can log in with username and password and receive a JWT stored in an httpOnly cookie
- [x] **AUTH-03**: User session persists across browser refresh via refresh token (30-day validity)
- [x] **AUTH-04**: User can log out, invalidating their session
- [x] **AUTH-05**: Access token (15-min) is transparently refreshed via refresh token endpoint

### Admin (ADMN)

- [x] **ADMN-01**: Admin can generate one-time invite codes for new user registration
- [x] **ADMN-02**: Admin can view the list of all users and their roles
- [x] **ADMN-03**: Admin can change a user's role (admin / user) or deactivate an account

### Deck Management (DECK)

- [x] **DECK-01**: User can create a deck with a title and optional description
- [x] **DECK-02**: User can view all their own decks on the decks page
- [x] **DECK-03**: User can edit a deck's title and description
- [x] **DECK-04**: User can delete a deck (and all its cards and progress)
- [x] **DECK-05**: User can set deck visibility: private, shared (specific users), or public (explore page)

### Card Management (CARD)

- [x] **CARD-01**: User can create a card in a deck with front and back content (Kartex format)
- [x] **CARD-02**: User can edit an existing card's front, back, or tags
- [x] **CARD-03**: User can delete a card from a deck
- [x] **CARD-04**: User can add freeform tags to a card
- [x] **CARD-05**: Card content renders Markdown text (via react-markdown)
- [x] **CARD-06**: Card content renders inline math expressions (`$...$`) via KaTeX
- [x] **CARD-07**: Card content renders block math expressions (`$$...$$`) via KaTeX
- [x] **CARD-08**: Card content renders `#typst` blocks via Typst WASM (typst.ts)
- [x] **CARD-09**: Card content renders inline images (PNG, JPEG, WebP, GIF) from uploaded media
- [x] **CARD-10**: Card content renders audio files (MP3, OGG, WAV) with a native HTML audio player
- [x] **CARD-11**: Card content renders external video links (YouTube, Vimeo) as embedded players
- [x] **CARD-12**: Card content renders fenced code blocks with syntax highlighting (highlight.js)

### Study & Learning (STDY)

- [x] **STDY-01**: User can start a spaced repetition session showing all cards due today across all decks (SM-2)
- [x] **STDY-02**: During a study session, each card flip is followed by a 4-key recall rating (1=Again, 2=Hard, 3=Good, 4=Easy)
- [x] **STDY-03**: SM-2 algorithm updates ease factor, interval, and next review date for each rating
- [x] **STDY-04**: User can start a deck mode session (all cards in one deck, sequentially; SM-2 progress saved)
- [x] **STDY-05**: User can start an exam mode session (time limit; SM-2 progress not saved)
- [x] **STDY-06**: Dashboard shows all cards due today across all decks with a count per deck
- [x] **STDY-07**: Dashboard shows study statistics: total cards reviewed today, current study streak

### Import (.kartex) (IMPT)

- [x] **IMPT-01**: User can upload a `.kartex` file on the import page and see a preview of parsed cards before importing
- [x] **IMPT-02**: User can upload a `.kartex.zip` bundle (deck.kartex + media/ folder) with preview before importing
- [x] **IMPT-03**: Importing creates a new deck and all cards from the parsed `.kartex` file
- [x] **IMPT-04**: Importing a `.kartex.zip` bundle stores bundled media files and links them to the created cards
- [x] **IMPT-05**: Import preview renders card content using the Kartex renderer (Markdown, math, Typst)

### Media Storage (MDIA)

- [x] **MDIA-01**: Images (PNG, JPEG, WebP, GIF) can be uploaded and are stored on the backend's local Docker volume
- [x] **MDIA-02**: Audio files (MP3, OGG, WAV) can be uploaded and are stored on the backend's local Docker volume
- [x] **MDIA-03**: All file uploads are validated by both MIME type header and magic bytes (first bytes of file)
- [x] **MDIA-04**: Maximum upload file size is configurable via environment variable (default: 10 MB)

### Sharing & Collaboration (SHAR)

- [x] **SHAR-01**: Deck owner can share a deck with a specific user granting READ or EDIT permission
- [x] **SHAR-02**: Deck owner can revoke a user's access to a shared deck
- [x] **SHAR-03**: Deck owner can make a deck public so it appears on the explore page
- [x] **SHAR-04**: Any logged-in user can browse public decks on the /explore page
- [x] **SHAR-05**: User can fork a public or shared deck into their own collection to edit it independently
- [x] **SHAR-06**: Each user's SM-2 learning progress is stored independently (progress is never shared between users)

### Infrastructure (INFR)

- [x] **INFR-01**: Full application runs with `docker compose up -d` after setting JWT_SECRET and DB_PASSWORD in `.env`
- [x] **INFR-02**: Hono serves the React SPA (static files via serveStatic) and handles all API routes *(override: Nginx removed per D-05/D-06)*
- [x] **INFR-03**: All API endpoints except `/api/auth/login` and `/api/auth/refresh` require a valid JWT
- [x] **INFR-04**: Rate limiting middleware is applied to authentication endpoints (login, register, refresh)
- [x] **INFR-05**: CORS is restricted to own domain only (no wildcard)
- [x] **INFR-06**: All secrets (JWT_SECRET, DB_PASSWORD) are sourced from `.env` only — no hardcoded values
