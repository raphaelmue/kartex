# Requirements Archive: Kartex v1.3.0 Stats & Import Update

**Milestone:** v1.3.0 Stats & Import Update
**Status:** ✅ SHIPPED 2026-06-11
**Archived:** 2026-06-11

All 12/12 requirements satisfied at milestone close.

## Learning Statistics (STATS)

- [x] **STATS-01**: Dashboard displays total cards reviewed (all time) and this week
- [x] **STATS-02**: Dashboard displays retention rate (% ratings ≥ Good in last 30 days), showing "No data yet" when review history is empty
- [x] **STATS-03**: Dashboard displays card difficulty breakdown (Easy / Good / Hard / Again counts), showing "No data yet" when review history is empty
- [x] **STATS-04**: Dashboard displays per-deck progress summary (due, mastered, in-learning)
- [x] **STATS-05**: Each card rating is recorded in a new `ReviewLog` table (userId, cardId, deckId, rating, reviewedAt) inside the existing `POST /api/study/rate` transaction

## Deck Update via Import (IMP)

- [x] **IMP-01**: User can upload a `.kartex` file from the Deck Detail page to update an existing deck
- [x] **IMP-02**: A preview modal shows the diff (added / updated / unchanged / removed card counts) before the user commits
- [x] **IMP-03**: Cards matched by `kartexId` field are updated in place (content refreshed, SM-2 progress preserved)
- [x] **IMP-04**: Cards present in the file but absent in the deck are added as new cards
- [x] **IMP-05**: Cards present in the deck but absent in the file are listed as "removed" in the preview
- [x] **IMP-06**: User can toggle "keep removed cards" on the confirmation dialog; when on (default), removed cards are kept; when off, they are deleted
- [x] **IMP-07**: The `.kartex` format accepts an optional `id:` field per card block; existing files without `id:` import normally (backward compatible)
