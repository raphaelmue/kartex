| Muted text | `text-muted-foreground` | hsl(0 0% 45%) | hsl(0 0% 64%) | Toggle labels, section headers, due card count, inactive deck visual treatment |

1. Switch `checked` state (shadcn Switch uses `data-[state=checked]:bg-primary` internally)

3. Active segmented size button (`variant="default"`)
4. "Start session" primary CTA button

**Inactive deck visual treatment (DecksPage):** Apply `opacity-60` to the entire `<Card>` when `deck.isActive === false`. This visually communicates inactive status without hiding the card or removing its actions. The toggle remains fully visible and interactive at 100% opacity via a wrapper that escapes the opacity.

All new UI must use only semantic CSS variable tokens. Never hardcode hex or use `bg-gray-*` / `bg-zinc-*` in new JSX.

Source: `apps/frontend/src/index.css`, `08-UI-SPEC.md §Color`.

## Component Contracts

### 1. isActive Toggle — DecksPage Card Footer (DECK-01)

**Placement:** Inside `<CardFooter>` of each deck card, prepended before the existing action buttons. The footer already uses `flex items-center gap-2`.

**Structure:**
```tsx
<div className="flex items-center gap-2 mr-auto">
  <Switch
    checked={deck.isActive}
    onCheckedChange={(checked) => void handleToggleActive(deck.id, checked)}
    aria-label={t('decks.toggleActive')}
    id={`active-${deck.id}`}
  />
  <label htmlFor={`active-${deck.id}`} className="text-sm text-muted-foreground cursor-pointer">
    {t('decks.activeLabel')}
  </label>
</div>
```

- `mr-auto` on the toggle wrapper pushes the existing action buttons (Study, Open, Edit, Delete) to the right, preserving current button layout.
- The `<Switch>` component from shadcn — no `className` override needed; default sizing (h-6 w-11) is sufficient.
- `aria-label` is redundant when `id`/`htmlFor` pair is present but included for extra screen reader clarity.
- The toggle triggers an optimistic UI update: flip `deck.isActive` immediately in local state, then `PATCH /api/decks/:id` with `{ isActive: boolean }`. On API error, revert the optimistic update and show a Sonner toast.

**Inactive card visual:** Wrap the entire `<Card>` in:
```tsx
<div className={deck.isActive ? '' : 'opacity-60'}>
  <Card>...</Card>
</div>
```
The outer `<div>` holds the opacity; the `<Switch>` inside the CardFooter stays visually unaffected because the opacity applies to the card as a whole (the switch is part of the card, so it dims too — this is intentional and communicates the inactive state).

**State table:**

| `deck.isActive` | Switch visual | Card opacity | Study button behavior |
|-----------------|--------------|--------------|----------------------|
| `true` | Thumb right, track filled (`bg-primary`) | 100% | Normal |
| `false` | Thumb left, track empty (`bg-input`) | 60% | Normal (deck-specific study still works) |

Note: Inactive decks are excluded from the /study global queue only. The deck's own /decks/:id/learn route continues to work regardless of isActive.

### 3. /study Start Screen — New Component Replacing Auto-Start (DECK-03, DECK-04)

**Current behavior:** `isGlobalSR === true` → `committedConfig` is set to `{ mode: 'sr', tags: new Set(), size: 'all', count: 1 }` immediately on mount → cards load without any user interaction.

**New behavior:** When `isGlobalSR === true` AND `committedConfig === null`, render the start screen. The start screen allows the user to select decks and session size before committing.

**Page structure** (mirrors existing mode selector `max-w-lg mx-auto py-12 px-4` wrapper):

```

```

### 4. Deck Picker List (DECK-03)

**Outer container:**
```tsx
<div className="border border-border rounded-lg overflow-hidden">
  {activeDecks.map((deck, i) => (
    <DeckPickerItem key={deck.id} ... />
  ))}
</div>
```

**DeckPickerItem structure:**
```tsx
<div
  className={`flex items-center gap-3 px-4 py-2 cursor-pointer hover:bg-muted/50 ${
    i < activeDecks.length - 1 ? 'border-b border-border' : ''
  }`}
  onClick={() => toggleDeckSelection(deck.id)}
>
  <Checkbox
    checked={selectedDeckIds.has(deck.id)}
    onCheckedChange={() => toggleDeckSelection(deck.id)}
    id={`deck-picker-${deck.id}`}
    aria-label={deck.title}
  />
  <div className="flex-1 min-w-0">
    {/* deck.title is user content — not translated (D-07) */}
    <p className="text-sm font-medium truncate">{deck.title}</p>
    <p className="text-xs text-muted-foreground">
      {t('study.nCardsDue', { count: deck.dueCount })}
    </p>
  </div>
</div>
```

- All active decks are **pre-checked** on mount (`selectedDeckIds` initialized as a `Set` of all active deck IDs).
- Clicking anywhere on the row (not just the checkbox) toggles the deck — the row is `cursor-pointer` and the `onClick` on the wrapper handles it.
- Checkbox `onCheckedChange` also fires for keyboard / direct checkbox interaction (both paths call `toggleDeckSelection`).
- `flex-1 min-w-0` on the text container prevents overflow — `truncate` on the title handles long names.
- Due count is loaded from `/api/study/due` prefetch on mount (same call pattern as existing `deckDueCount` prefetch in `StudySessionPage.tsx` line 248–250). The due count shown is the count from active decks only.
- Border separator between items: `border-b border-border` on all items except the last.

**Checkbox state:**

| `selectedDeckIds.has(deck.id)` | Checkbox | Row background |
|-------------------------------|----------|----------------|
| `true` (pre-checked default) | Filled (`bg-primary`) | Transparent |
| `false` (user unchecked) | Empty | Transparent |
| Row hovered | — | `bg-muted/50` |

### 5. Session Size Picker — /study Start Screen (DECK-04)

Exact reuse of the existing segmented button row from `StudySessionPage.tsx` lines 355–382. No changes to the pattern.

```tsx
<div>
  <p className="text-xs font-semibold text-muted-foreground uppercase tracking-wide mb-2">
    {t('study.sessionSize')}
  </p>
  <div className="flex items-center gap-2 flex-wrap">
    {SIZE_OPTIONS.map((opt) => (
      <Button
        key={String(opt.value)}
        size="sm"
        variant={sessionSize === opt.value ? 'default' : 'outline'}
        onClick={() => setSessionSize(opt.value)}
        type="button"
      >
        {opt.label}
      </Button>
    ))}
    {sessionSize === 'custom' && (
      <Input
        type="number"
        min={1}
        value={customCount}
        onChange={(e) => setCustomCount(Math.max(1, parseInt(e.target.value, 10) || 1))}
        className="w-20 h-8"
      />
    )}
  </div>
</div>
```

- The parenthetical "(SR mode only)" from the deck-specific mode selector is **omitted** on the /study start screen — the global session is always SR mode, so the qualifier is unnecessary.
- SIZE_OPTIONS definition: same as existing `StudySessionPage.tsx` internal array — `[{ label: t('study.sizeAllDue'), value: 'all' }, { label: '10', value: 10 }, { label: '20', value: 20 }, { label: t('study.sizeCustom'), value: 'custom' }]`.
- Default selected: `'all'` (same as existing deck-specific session default).

```tsx
<Button
  size="lg"
  className="w-full mt-4"
  disabled={selectedDeckIds.size === 0}
  onClick={handleStartSession}

  {t('study.startSession')}
```

- `size="lg"` — matches the "Return to Dashboard" button in `SessionRunner` done state (line 101).
- `w-full` — spans the full `max-w-lg` container width.
- `mt-4` (16px) — separates from the session size picker above.
- Disabled when `selectedDeckIds.size === 0` (user has unchecked all decks) — button shows disabled state via shadcn `Button` default disabled styles (`opacity-50 cursor-not-allowed`).
- On click: sets `committedConfig` with `{ mode: 'sr', tags: new Set(), size: sessionSize, count: customCount, deckIds: [...selectedDeckIds] }`. The card loading effect reads `committedConfig` and fetches only from the selected decks.

## Responsive Behavior

**isActive toggle (DecksPage):**
- The deck card `<CardFooter>` already wraps in narrow viewports; the toggle group with `mr-auto` will appear on its own line when the footer wraps, which is acceptable. The toggle and label stay inline with each other (`flex items-center gap-2`).
- On very narrow screens (< 320px): the toggle label may be omitted via `hidden sm:inline` if needed — default is to always show the label.

**isActive toggle (DeckDetailPage):**
- The header button group already uses `flex items-center gap-2` with `items-start justify-between` on the outer wrapper. Toggle label text is short ("Active") and wraps gracefully.

**/study start screen:**
- Inherits `max-w-lg mx-auto py-12 px-4` wrapper — identical to existing mode selector screen.
- Deck picker list: `border rounded-lg overflow-hidden` with stacked items — scrolls naturally on narrow viewports; no horizontal overflow.
- Segmented size row: `flex-wrap` allows buttons to wrap to a second line on < 320px — same as existing behavior.

## States and Edge Cases

### No Active Decks (user has set all decks to inactive)

When `/api/decks` returns no decks with `isActive === true`:

Render inside the deck picker section container in place of the list:
```tsx
<div className="flex flex-col items-center justify-center py-8 gap-2 text-muted-foreground border border-border rounded-lg">
  <BookOpen className="h-8 w-8" aria-hidden="true" />
  <p className="text-sm font-medium">{t('study.noActiveDecks')}</p>
  <p className="text-xs text-center">{t('study.noActiveDecksHint')}</p>
</div>
```

The "Start session" CTA remains rendered but is `disabled` (since `selectedDeckIds.size === 0`). The user must go to the Decks page to activate at least one deck before starting a global session.

No navigation redirect — the user sees a clear explanation with a hint to go activate decks.

### User Unchecks All Decks in Picker

- `selectedDeckIds` becomes an empty Set.
- "Start session" button becomes disabled (`disabled={selectedDeckIds.size === 0}`).
- No inline error message — the disabled button state is sufficient feedback.

### All Selected Decks Have 0 Due Cards

- `selectedDeckIds` is non-empty, so the CTA is enabled.
- User clicks "Start session" → `committedConfig` is committed → card loading effect runs → `/api/study/due` returns 0 cards matching the selected decks → `SessionRunner` renders the "all caught up" empty state (existing: `CheckCircle2` icon + "No cards to study!" + "All caught up." + Return to Dashboard button).
- No start-screen validation for this case — it is handled downstream by `SessionRunner`.

### Deck Has Cards But None Due

The due count shown in the deck picker is `0` — rendered as `t('study.nCardsDue', { count: 0 })` → "0 cards due". The deck is still selectable (pre-checked). This is intentional: the user may want to include the deck for future-proofing even if no cards are due today.

### Only One Active Deck

Deck picker shows a single item (no border-b separator). The list renders normally. CTA is enabled (the single deck is pre-checked).

### DecksPage: Toggle fires during API request

Optimistic update: local `isActive` state flips immediately. If the `PATCH` fails, revert to the previous value and show `toast.error(t('decks.failedToToggle'))`. The switch snaps back to its previous position. No loading spinner on the switch — the optimistic state is the primary feedback.

### DeckDetailPage: Shared deck (user is not owner)

`isActive` is a per-owner preference (v1.2 scope: owner-only). The toggle is **hidden** for shared decks where `deck.ownerId !== user.id`. The toggle only renders when the current user is the deck owner.

Condition: `{deck.ownerId === user?.id && (<Switch .../>)}` in DeckDetailPage header. On DecksPage: `{!deck.sharedByUsername && (<Switch .../>)}` mirrors the existing Edit/Delete conditional at line 139.

## Accessibility Contract

- `<Switch>` and `<Checkbox>` are Radix UI primitives (via shadcn) — both are keyboard-accessible and announce state via ARIA internally.
- `Switch`: paired with a `<label>` via `htmlFor`/`id` — clicking the label activates the switch.
- Deck picker row: the entire row `<div>` has `onClick` + `cursor-pointer`; the `<Checkbox>` inside handles its own keyboard activation (Space key). Row does **not** get `role="button"` to avoid double-announcement — the Checkbox is the semantic control.
- "Start session" button: `disabled` attribute is set when no decks selected — screen readers announce "Start session, dimmed, button".
- Empty state (no active decks): `<BookOpen>` has `aria-hidden="true"`; text content is the accessible announcement.
- isActive Switch on DeckDetailPage: only rendered when the user is the owner — no toggle shown to non-owners (no need to explain why it is absent).
- All `<Button>` chips and size buttons must have `type="button"` to prevent accidental form submission.
- `aria-live` regions: not needed for this phase — the toggle's optimistic state and toast provide sufficient feedback for screen readers via Sonner's existing live region.

## Animation and Transition

No new animations introduced.

- `<Switch>` thumb animation: shadcn default (`transition-transform`) — no override.
- `<Checkbox>` check animation: shadcn default — no override.
- Inactive deck card opacity (`opacity-60`): no transition — applies immediately on state change. Adding `transition-opacity duration-150` is acceptable but not required; default is no transition.
- /study start screen appearance: the screen renders when `committedConfig === null` — no entry animation (same as existing mode selector screen).
- Deck picker item hover: `hover:bg-muted/50` — CSS hover, no explicit transition class needed (Tailwind default is instant).
