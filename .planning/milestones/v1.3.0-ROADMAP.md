## Overview

Learning statistics surfaced on the dashboard (total reviewed, retention rate, difficulty breakdown, per-deck progress) via a new `ReviewLog` table and `/api/stats/summary` endpoint. Deck update-via-import: upload a `.kartex` file to update an existing deck in place — cards matched by stable `id:` field have their content refreshed while SM-2 progress is preserved; new cards are added; removed cards are controllable via a keepRemoved toggle.

## Milestone Summary

**Key Accomplishments:**
1. `ReviewLog` table (userId, cardId, deckId, rating, reviewedAt) written inside every `POST /api/study/rate` transaction — provides the data foundation for future learning analytics
2. `Card.kartexId` nullable field with `@@unique([deckId, kartexId])` — stable per-deck card identity for import-update matching
3. Dashboard now shows 4 stat chips: Total Reviewed, Retention Rate (null on empty history), Difficulty Breakdown (null on empty), Per-Deck Progress (due/mastered/in-learning)
4. `.kartex` parser updated to parse optional `id:` field per card block — backward compatible (files without `id:` continue to work)
5. `computeDiff` algorithm matches cards by `kartexId` — correctly handles added/updated/unchanged/removed categories with a kartexId=null guard to protect manually-created cards
6. `DeckUpdateModal` two-phase dialog (preview → apply) with keepRemoved toggle — apply executes as a single `prisma.$transaction`

**Key Decisions:**
- ReviewLog write inside existing cardProgress.upsert transaction — no separate endpoint; atomicity guaranteed
- card.updateMany unusable for content updates — individual card.update calls used inside transaction (each card has different data)
- computeDiff: kartexId=null cards excluded from removedIds — manually-created cards are never auto-deleted (CR-02 fix)
- DeckUpdateModal: res.ok checked in both runPreview and runApply — HTTP 4xx/5xx surface as user-visible errors (CR-01 fix)
- Promise.allSettled replaced by two independent void calls for dashboard parallel fetch — React 18 batching issue made skeleton state unreachable under allSettled (CR-02 Phase 15)
- runPreview/runApply declared before useEffect — ESLint no-use-before-define compliance

**Tech Debt Deferred to v1.4:**
- 9 backend stats test stubs (`stats-summary.test.ts`) — never upgraded from it.todo to real HTTP-layer assertions
- No try/catch in stats.ts Prisma queries (unstructured 500 on DB error)
- `deckUpdate.fileTooLarge` i18n key defined but unused
- VALIDATION.md status files stale (nyquist_compliant: false) for phases 15 and 16

**Issues Resolved:**
- ESLint `no-use-before-define` in DeckUpdateModal.tsx — runPreview/runApply moved above useEffect (commit 6cba6ac)
- Shared package dist stale locally — rebuilt; CI unaffected (always builds fresh)
- Pre-existing backend kartex-parser-id.test.ts failures (3 tests) — resolved; caused by stale local dist (IMP-07 implementation was correct)
