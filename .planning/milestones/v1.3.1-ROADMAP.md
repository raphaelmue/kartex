# Milestone v1.3.1: Bug Fixes & Mobile Polish

**Status:** ✅ SHIPPED 2026-06-12
**Phases:** 17–18
**Total Plans:** 4
**Audit:** superseded — audit was generated before Phase 18 executed; all 3/3 requirements satisfied on ship

## Overview

Two-phase patch release fixing mobile UI regressions and completing library deck toggle support. Phase 17 resolved mobile layout overflow issues (stats table, AppShell drawer) and replaced inline deck action buttons with a ⋮ DropdownMenu to fix card boundary overflow on all viewports. Phase 18 added per-user `DeckShare.isActive` state so users can activate or deactivate public/shared decks they added from the Explore page, giving them the same study queue control as owned decks.

## Phases

### Phase 17: Mobile UI Polish

**Goal:** Mobile viewport renders cleanly and deck card action buttons are fully contained — no overflow on any screen size
**Depends on:** Nothing (pure frontend)
**Requirements:** MOB-01, DECK-05
**Plans:** 2 plans

Plans:
- [x] 17-01: Wrap StatsSummaryPanel per-deck Table in overflow-x-auto; add overflow-x-hidden to AppShell main (MOB-01)
- [x] 17-02: Install DropdownMenu + AlertDialog; restructure DecksPage CardFooter with ⋮ menu replacing inline Edit/Delete; remove confirmDeleteId (DECK-05)

**Success Criteria (all met):**
1. ✅ On a 375px mobile viewport, main content area has appropriate padding and no element overflows its container
2. ✅ On a 375px mobile viewport, deck card action buttons are fully visible within the card boundary
3. ✅ On a 1280px desktop viewport, deck card action buttons are fully visible within the card boundary
4. ✅ No regression in existing desktop layout after changes

**Key decisions:**
- `overflow-x-auto` wrapper placed only around `<Table>`, not the heading `<p>` — heading stays visible without scrolling
- `overflow-x-hidden` added unconditionally to AppShell `<main>` — always-in-DOM `-translate-x-full` drawer can expand scrollable area in some browsers
- `deleteTargetId` replaces `confirmDeleteId` — AlertDialog open state is single source of truth for delete flow
- Single `AlertDialog` outside map loop — one shared instance avoids N dialog instances in DOM when N deck cards rendered
- `DropdownMenuItem` destructive style via `className` — shadcn DropdownMenuItem has no variant prop

**Files changed:** StatsSummaryPanel.tsx, AppShell.tsx, DecksPage.tsx, dropdown-menu.tsx (new), alert-dialog.tsx (new), en.json, de.json

### Phase 18: Library Deck Toggle

**Goal:** Users can activate or deactivate decks they've added from the Explore page, giving them the same study queue control as owned decks
**Depends on:** Nothing (can run in parallel with Phase 17)
**Requirements:** LIB-01
**Plans:** 2 plans

Plans:
- [x] 18-01: Schema migration (DeckShare.isActive), UpdateLibrarySchema, GET /api/decks isActive override, PATCH /api/decks/:id/library endpoint, GET /api/study/due filter fix (LIB-01 backend)
- [x] 18-02: handleToggleLibraryActive handler, library CardFooter Switch, DecksPage.test.tsx LIB-01 cases, library-toggle.test.ts backend stubs (LIB-01 frontend)

**Success Criteria (all met):**
1. ✅ A library deck shows an active/inactive toggle on DecksPage identical in appearance to the owned-deck toggle
2. ✅ Toggling a library deck active/inactive persists after page refresh
3. ✅ Starting a /study session only includes library decks the user has marked active
4. ✅ Toggling a library deck does not affect the deck owner's isActive state for that deck

**Key decisions:**
- `DeckShare.isActive Boolean @default(true)` — per-user activation independent of `Deck.isActive` (owner's toggle)
- `isActive: r.isActive` override in `sharedRows.map` placed before `sharedByUsername` — shadows `r.deck.isActive` with `DeckShare.isActive`
- OR[1] `deckFilter` for shared decks drops `Deck.isActive` — `DeckShare.isActive` already gates; owner's toggle must not exclude shared deck from recipient's study queue
- Library Switch uses `id=active-lib-{id}` prefix — prevents DOM id collision with owned-deck Switch `id=active-{id}`
- Hand-written migration SQL (consistent with 10-02, 18-01 pattern) — `prisma migrate deploy` unavailable without DATABASE_URL

**Files changed:** schema.prisma, migration.sql (new), deck.ts (shared schemas), decks.ts, study.ts, DecksPage.tsx, DecksPage.test.tsx, library-toggle.test.ts (new)
