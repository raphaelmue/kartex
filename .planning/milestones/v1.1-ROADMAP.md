# Milestone v1.1: Study Experience & Polish

**Status:** ✅ SHIPPED 2026-06-01
**Phases:** 7–9
**Total Plans:** 8

## Overview

UX improvements to the study loop and app shell: tag filtering, session size control, always-shuffle, mobile sidebar with overlay drawer, app footer, and react-i18next internationalization (frontend only). Shipped in 2 days across 3 phases.

## Phases

### Phase 7: App Shell

**Goal**: The app shell works correctly on all screen sizes and carries attribution
**Depends on**: Phase 6 (v1.0 complete)
**Requirements**: SHELL-01, SHELL-02, SHELL-03
**Plans**: 1 plan

Plans:

- [x] 07-01-PLAN.md — Test stub (Wave 0) + Vite version injection + AppShell responsive implementation (mobile topbar, overlay drawer, footer) — completed 2026-05-31

**Success Criteria:**
1. On a screen narrower than 768px, the sidebar is hidden by default and a hamburger button is visible ✓
2. Tapping the hamburger opens the sidebar as an overlay drawer without pushing page content ✓
3. The app footer is visible on every page, showing the version number, copyright, and any configured links ✓

**Key Decisions:**
- `createRequire` (not `resolveJsonModule`) for Vite version injection — incompatible with `moduleResolution: bundler + allowImportingTsExtensions`
- CSS-transform always-in-DOM drawer (not conditional render) — enables 200ms exit animation
- Drawer at z-50, backdrop at z-40 per UI-SPEC Z-index stacking

### Phase 8: Study UX

**Goal**: Users can target exactly what they want to study before starting a session
**Depends on**: Phase 7
**Requirements**: STUDY-01, STUDY-02, STUDY-03, STUDY-04
**Plans**: 4 plans (3 original + 1 UAT gap closure)

Plans:

- [x] 08-01-PLAN.md — Wave 0: Failing test stubs for STUDY-01/02/03 (StudySessionPage) and STUDY-04 (DeckDetailPage) — completed 2026-05-31
- [x] 08-02-PLAN.md — Wave 1: Implement tag filter + session size picker + shuffle in StudySessionPage.tsx (STUDY-01, STUDY-02, STUDY-03) — completed 2026-05-31
- [x] 08-03-PLAN.md — Wave 2: Implement tag-sectioned layout in DeckDetailPage.tsx (STUDY-04) + full verification gate — completed 2026-05-31
- [x] 08-04-PLAN.md — UAT gap closure: Replace grouped card sections with flat table + tag filter chip bar (STUDY-04c) — completed 2026-06-01

**Success Criteria:**
1. Before starting a study session, the user can select one or more tags to limit which cards appear ✓
2. Before starting a session, the user can choose a card count: All due, 10, 20, or a custom number ✓
3. Cards within a session are always presented in a shuffled (random) order ✓
4. On the deck detail page, cards can be filtered by tag via a chip bar above a flat table ✓

**Key Decisions:**
- `availableTags` derived from `allCardsRes` prefetch (not filtered `cards` state) — prevents chip list shrinking when filter active
- `groupCardsByFirstTag` extracted to `src/utils/groupCardsByFirstTag.ts` — keeps DeckDetailPage under 500 lines
- Phase 8 Plan 04 (UAT gap closure): Replaced h3-sectioned layout with flat table + tag filter chip bar after UAT STUDY-04c failures
- `filterTag` state toggle: clicking active chip clears (sets null), clicking inactive chip sets as filter
- `filteredCards` uses `Array.includes` — multi-tag cards appear under any matching filter

### Phase 9: Internationalization

**Goal**: The app UI is fully translatable and users can switch language at runtime
**Depends on**: Phase 8
**Requirements**: I18N-01, I18N-02, I18N-03
**Plans**: 3 plans

Plans:

**Wave 1**
- [x] 09-01-PLAN.md — Wave 1: i18n infrastructure (packages, en/de locales, i18n.ts, type augmentation, test setup, failing LanguageToggle stub) — completed 2026-06-01

**Wave 2** *(blocked on Wave 1 completion)*
- [x] 09-02-PLAN.md — Wave 2: AppShell + language toggle + shared components + modals string wrapping — completed 2026-06-01

**Wave 3** *(blocked on Wave 2 completion)*
- [x] 09-03-PLAN.md — Wave 3: all 9 page files string wrapping + phase verification gate — completed 2026-06-01

**Success Criteria:**
1. The frontend uses react-i18next and locale JSON files exist under `apps/frontend/src/locales/` ✓
2. Every visible UI string renders via a `t()` call — no hardcoded English strings in JSX ✓
3. A language selector is accessible in the UI and switching language updates all strings without a page reload ✓

**Key Decisions:**
- i18next v26 removed `initImmediate` from `InitOptions` — omit it; v26 init is synchronous without async backend
- `changeLanguage` mock requires `as any` cast — `TFunction` brand type in i18next v26 is not satisfiable by a plain function mock
- `labelKey` pattern for `navItems`/`RATINGS` arrays — store key strings at module scope; call `t(key)` inside component render to satisfy React hook rules
- `EXAM_DURATIONS`/`SIZE_OPTIONS` moved inside component — needed `t()` access; module-scope arrays can't call hooks
- User content is always interpolated as values (`{{deckTitle}}`), never used as translation keys (D-07)
- 254 keys in both `en.json` and `de.json` with full parity

## Milestone Summary

**Key Accomplishments:**
1. Responsive AppShell with mobile hamburger topbar, CSS-transform overlay drawer (200ms slide), and sticky footer with build-time version injection
2. Tag-based study session filter (OR logic, multi-select) + session size picker (All/10/20/custom) + always-shuffle
3. DeckDetailPage flat table with tag filter chip bar (flat table replaces h3-grouped layout after UAT)
4. Full react-i18next setup with 254 en/de locale keys, LanguageToggle button, all 9 pages and shared components translated

**Decimal Phases:** None

**Key Decisions:**
- CSS-transform always-in-DOM drawer (not conditional render) — enables exit animation
- `createRequire` for Vite version injection — `resolveJsonModule` incompatible with project tsconfig
- `availableTags` from prefetch — prevents chip list collapse when filter active
- Phase 08-04 UAT gap closure: flat table + tag filter chip bar preferred over h3 section groups after user testing
- i18next v26: `initImmediate` removed; synchronous init without async backend plugin
- User content as interpolation values only — never as translation keys (prevents i18n injection)

**Issues Resolved:**
- STUDY-04c: UAT revealed grouped h3 layout failed for multi-tag cards — resolved by flat table + filter bar (08-04)
- Phase 8 ROADMAP plan count corrected: 4 plans (not 3 as initially documented)

**Issues Deferred:**
- Backend i18n (I18N-FUTURE-01) — English-only backend messages acceptable for v1.1
- German locale as shipped locale (I18N-FUTURE-02) — de.json exists with full parity but is placeholder German
- Tag hierarchy / nested topics — deferred to v2

**Technical Debt Incurred:**
- German (de.json) translations are machine-assisted placeholder, not production-quality translations — needs a native speaker review before shipping to German users
- `groupCardsByFirstTag` utility retained for its tests even though DeckDetailPage no longer uses it (flat table replaced the grouped layout)
