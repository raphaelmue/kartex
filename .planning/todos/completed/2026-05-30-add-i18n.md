## Problem

The app currently has all UI strings hardcoded in English. As the user base potentially grows beyond a single language, internationalizing the frontend (and possibly backend error messages) would make Kartex usable for non-English speakers. This surfaced as a user-requested feature during Phase 6 UAT.

## Solution

TBD — likely react-i18next (i18next ecosystem) for the frontend with a locale JSON structure under `apps/frontend/src/locales/`. Backend error messages (Hono) could use a separate i18n layer or stay English-only in v1. Scope and priority to be determined in next milestone planning.
