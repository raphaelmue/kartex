## E2E User Flows — 2/2 Complete

### Flow 1: Study → Stats visible on dashboard

1. User rates a card via `POST /api/study/rate` → `prisma.$transaction` writes `CardProgress` + `ReviewLog` row ✅
2. User views dashboard → `DashboardPage` fetches `/api/stats/summary` in parallel with `/api/dashboard/stats` ✅
3. `stats.ts` queries `ReviewLog` (STATS-02/03) and `CardProgress` (STATS-01/04) ✅
4. `StatsSummaryPanel` renders chips with live data; null on empty history ✅
5. Stats fetch failure → silent empty state, dashboard hero unaffected ✅

### Flow 2: Import-update deck without losing SM-2 history

1. User opens DeckDetailPage (owner) → "Update from file" button visible ✅
2. User selects `.kartex` file → hidden input triggers → `DeckUpdateModal` opens with auto-preview ✅
3. `POST /api/decks/:id/update/preview` parses file, calls `computeDiff` (kartexId matching), returns diff counts ✅
4. Modal shows added/updated/unchanged/removed chips + keepRemoved switch ✅
5. User clicks Apply → `POST /api/decks/:id/update/apply` executes `prisma.$transaction` (createMany + update loop + conditional deleteMany) ✅
6. `CardProgress` records untouched (only `frontContent`, `backContent`, `tags` updated) ✅
7. `onSuccess` → `fetchCards` refreshes deck card list ✅
