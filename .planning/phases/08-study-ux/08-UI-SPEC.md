## Spacing Scale

All values are multiples of 4. References use Tailwind utility classes mapped to this scale.

| Token | Value | Tailwind Class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | gap-1, p-1 | Icon gap within chip, tag display gap |
| sm | 8px | gap-2, mb-2, px-2 | Chip row gap, label-to-control gap, section header bottom margin |
| md | 16px | gap-4, mb-4, px-4 | Default element spacing, action button row gap |
| lg | 24px | mb-6, py-6, gap-6 | Config section bottom margin, mode card bottom margin |
| xl | 32px | py-8, mt-8 | Page section separation (deck detail share section) |
| 2xl | 48px | py-12 | Page-level top padding (mode selector screen) |
| 3xl | 64px | py-16 | Empty state vertical padding |

Exceptions:
- Touch target minimum: 44px height on interactive chips — shadcn `Button size="sm"` at h-9 (36px) is acceptable given keyboard fallback; no override needed.
- Mode cards: `p-6` (24px) internal padding — matches existing pattern, do not change.
- Custom size input: `w-20 h-8` (width 80px, height 32px) — fixed narrow width to keep inline with segmented row.

Source: measured from existing `StudySessionPage.tsx` and `DeckDetailPage.tsx` patterns.

## Color

This project uses a neutral monochrome palette with CSS variables (HSL). Dark mode is toggled via `.dark` class on `<html>`. All color references use semantic tokens — never hardcoded hex.

| Role | CSS Variable | Light value | Dark value | Usage |
|------|-------------|-------------|------------|-------|
| Dominant (60%) | `bg-background` | hsl(0 0% 98%) | hsl(0 0% 4%) | Page background, main content area |
| Secondary (30%) | `bg-card`, `bg-muted`, `bg-secondary` | hsl(0 0% 100%) / hsl(0 0% 96%) | hsl(0 0% 9%) / hsl(0 0% 15%) | Mode cards, config section container, tag section dividers |
| Accent (10%) | `bg-primary` / `text-primary` | hsl(0 0% 9%) | hsl(0 0% 98%) | Reserved for: selected chip fill, active segmented button fill, primary CTA button |
| Destructive | `bg-destructive` | hsl(0 84% 60%) | hsl(0 62% 30%) | Card delete confirm button only |
| Muted text | `text-muted-foreground` | hsl(0 0% 45%) | hsl(0 0% 64%) | Section header labels, tag section headers, help text |
| Border | `border-border` | hsl(0 0% 90%) | hsl(0 0% 15%) | Mode card borders, config section separator border (if used), table row borders |

Accent reserved for:
1. Selected/active chip state (`variant="default"` → `bg-primary text-primary-foreground`)
2. Active segmented button state (`variant="default"`)
3. Primary CTA "Start session" / "Add Card" buttons

All new UI must produce identical contrast ratios in both light and dark mode — use only the semantic CSS variable tokens above. Never use hardcoded `bg-gray-*`, `bg-zinc-*`, or color hex in new JSX for Phase 8 additions.

Source: `apps/frontend/src/index.css` (full CSS variable declaration block).

## Component Contracts

### 1. Config Section (StudySessionPage — STUDY-01, STUDY-02)

**Placement:** Inside `if (!selectedMode)` return branch, between the `<p>` subtitle (line 256) and the first mode card `<div>` (line 259). Separated from mode cards by `mb-6` on the config section container.

**Outer container:**
```
<div className="mb-6 space-y-3">
```
- `space-y-3` (12px between label row and control row) between the two subsections.
- `mb-6` (24px) separates the config block from the mode cards below.
- Conditional render: `{availableTags.length > 0 && (...)}` — entire config section hidden if deck has no tags.

**Tag filter subsection:**
```
<div>
  <p className="text-xs font-semibold text-muted-foreground uppercase tracking-wide mb-2">
    Filter by tag
  </p>
  <div className="flex flex-wrap gap-2">
    {/* chips */}
  </div>
</div>
```
- Label: `text-xs font-semibold text-muted-foreground uppercase tracking-wide mb-2`
- Chip row: `flex flex-wrap gap-2` (8px gap between chips, wraps on narrow screens)

**Session size subsection:**
```
<div>
  <p className="text-xs font-semibold text-muted-foreground uppercase tracking-wide mb-2">
    Session size <span className="font-normal normal-case tracking-normal">(SR mode only)</span>
  </p>
  <div className="flex items-center gap-2 flex-wrap">
    {/* segmented buttons + optional custom input */}
  </div>
</div>
```
- Label: same class pattern as tag filter label; parenthetical "(SR mode only)" uses `font-normal normal-case tracking-normal` to de-emphasize.
- Button row: `flex items-center gap-2 flex-wrap`

### 2. Tag Filter Chip (STUDY-01)

```
<Button
  size="sm"
  variant={selectedTags.has(tag) ? 'default' : 'outline'}
  onClick={...}
  type="button"
>
  {tag}
</Button>
```

| State | `variant` | Visual effect |
|-------|-----------|---------------|
| Deselected (default) | `"outline"` | Border + transparent background, `text-foreground` |
| Selected | `"default"` | `bg-primary text-primary-foreground` (filled) |

- Size: `size="sm"` (h-9, px-3, text-sm) — consistent with existing mode card sub-labels.
- No custom className needed — shadcn `Button` variant handles all hover/focus/active states.
- Chip text: render tag name as-is (no truncation, no capitalization transform — display raw tag string from `card.tags[]`).
- Maximum chips in view: no limit — `flex-wrap` handles overflow gracefully.

### 3. Segmented Size Button Row (STUDY-02)

Four buttons in a row: **All due** / **10** / **20** / **Custom**

```
<Button size="sm" variant={sessionSize === opt.value ? 'default' : 'outline'} ...>
  {opt.label}
</Button>
```

| Option label | State value | Notes |
|-------------|-------------|-------|
| All due | `'all'` | Default active on mount |
| 10 | `10` | |
| 20 | `20` | |
| Custom | `'custom'` | Triggers inline input |

- Active option: `variant="default"` (filled)
- Inactive options: `variant="outline"` (bordered)
- All four use `size="sm"` — matches chip size for visual alignment.
- The four buttons are NOT wrapped in a `ButtonGroup` or connected border — they are spaced with `gap-2` and independently rounded (standard shadcn Button border-radius).

**Custom input (appears inline to the right when `sessionSize === 'custom'`):**
```
<Input
  type="number"
  min={1}
  value={customCount}
  onChange={...}
  className="w-20 h-8"
/>
```
- Width: `w-20` (80px) — narrow, intentionally compact.
- Height: `h-8` (32px) — slightly shorter than the buttons (h-9) but visually acceptable within the same row.
- Minimum value: 1 (enforced via `Math.max(1, parseInt(...) || 1)`).
- No maximum enforced in UI — backend will return fewer cards if count exceeds deck size.
- Placeholder: none (value always initialized to 1).

### 4. Tag Section Header (DeckDetailPage — STUDY-04)

```
<h3 className="text-sm font-semibold text-muted-foreground uppercase tracking-wide mb-2">
  {tag}
  <span className="font-normal normal-case tracking-normal ml-1">— {groupCards.length} cards</span>
</h3>
```

- Tag name: `uppercase tracking-wide` — consistent with all other section label patterns in the app.
- Card count: `font-normal normal-case tracking-normal ml-1` — visually subordinate to the tag name.
- "Untagged" section header: same class, but tag string is `"Untagged"` (capitalized literal, will render as "UNTAGGED" due to uppercase class — acceptable, marks it as a system category).
- Bottom margin: `mb-2` (8px) between header and the mini-table below.
- Section container: `<div className="mb-6">` wrapping header + table — 24px between sections.

### 5. Per-Section Mini-Table (DeckDetailPage — STUDY-04)

Each tag section renders a `<Table>` with the same column structure as the current flat table:

| Column | Width | Content |
|--------|-------|---------|
| # | `w-12` (48px) | 1-based index within the section (not global) |
| Front | auto | `card.frontContent`, truncated with `max-w-xs truncate` |
| Tags | auto | `<TagChips tags={card.tags} />` — unchanged existing component |
| Actions | auto | Edit / Delete buttons — unchanged existing pattern |

- `aria-label`: `Cards tagged {tag}` (e.g. `"Cards tagged biology"`, `"Cards tagged Untagged"`)
- The `<TableHeader>` row is rendered for every section (not only the first) — each mini-table is self-contained for accessibility.
- Row numbering (#) resets to 1 per section — uses `groupCards.map((card, i) => i + 1)`.

## Responsive Behavior

Both new UI blocks must work at all viewport widths. The AppShell main area provides `p-8` (32px) on all sides.

**Config section (StudySessionPage):**
- The mode selector wrapper is `max-w-lg mx-auto py-12 px-4` — config section inherits this constraint (max 512px wide on desktop).
- On narrow screens (< 400px): chip row wraps naturally (`flex-wrap`); segmented button row wraps naturally with custom input dropping to a second line — acceptable.
- On wide screens: all chips on one line if tag count is small (< 6 tags); segmented row always fits on one line (four compact buttons).

**Tag section headers (DeckDetailPage):**
- DeckDetailPage has no max-width wrapper — fills the main content area.
- Tables are already responsive (horizontal scroll on narrow viewports from the existing Table component).
- Section headers (h3) are `text-sm` — no responsive font size change needed.

## States and Edge Cases

### Config Section: No Tags Available

When `availableTags.length === 0` (deck cards have no tags, or deck has no cards yet):
- Entire config section `<div>` is not rendered (conditional on `availableTags.length > 0`).
- Session size picker is also hidden (it is nested inside the same conditional block).
- Mode cards render immediately below the subtitle, unchanged from current behavior.

### Config Section: All Tags Selected vs. None Selected

| selectedTags state | Filter behavior | Visual |
|-------------------|-----------------|--------|
| Empty Set (default) | All cards included | All chips show `variant="outline"` |
| One or more tags | OR filter; untagged cards excluded | Selected chips show `variant="default"` |

No "Select all" or "Clear" affordance is needed — clicking each selected chip deselects it (toggle behavior). Default state (no selection = all cards) is the most common case.

### Config Section: Custom Input with Invalid Entry

- Input: `type="number"` prevents non-numeric keyboard on mobile.
- Guard: `Math.max(1, parseInt(e.target.value, 10) || 1)` — NaN coerces to 1, value below 1 coerces to 1.
- No error message displayed — silent coercion to minimum (1). Value snaps on `onChange`, so the field always shows a valid integer.

### DeckDetailPage: Empty Deck (No Cards)

When `cards.length === 0`: render the existing empty state block (BookOpen icon + "No cards yet" text + optional Add Card button) outside the grouped sections. The `groupCardsByFirstTag` function is not called.

Empty state copy:
- Heading: **"No cards yet"** (existing — do not change)
- Body (owner/editor): **"Add your first card to this deck."** + Add Card button (existing)
- Body (viewer): **"This deck has no cards yet."** (existing)

### DeckDetailPage: Tag Section with a Single Card

Section renders normally — "1 cards" is grammatically incorrect but acceptable for v1.1 (i18n phase will address pluralization). The count renders as `{groupCards.length} cards` unconditionally.

### DeckDetailPage: Card with Multiple Tags

Card appears under its first tag only (`card.tags[0]`). No visual indicator on the card row that it belongs to additional tags — the Tags column already shows all tags via `<TagChips>`, which provides full context.

### DeckDetailPage: All Cards are Untagged

One section renders with header "UNTAGGED — N cards" containing all cards. No alphabetically-sorted sections appear before it.

## Accessibility Contract

- All `<Button>` chips must have `type="button"` to prevent accidental form submission.
- Custom number input: `<Input type="number" min={1}>` — browser renders accessible number field with spinner arrows.
- Tag section tables: each `<Table>` has a unique `aria-label` per section (e.g. `"Cards tagged biology"`).
- Section headers are `<h3>` — fits below existing `<h1>` (page title) in heading hierarchy.
- Mode cards use existing `role="button" tabIndex={0} onKeyDown` pattern — no changes to keyboard navigation.
- Chip toggle: `aria-pressed` attribute is not required (shadcn Button does not implement it by default); visual variant contrast is sufficient for sighted users; keyboard users can tab through chips (Button is natively focusable).
