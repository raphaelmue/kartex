## API fetch wrapper requirements
- All calls use credentials: 'include' for cookies
- On 401: attempt POST /api/auth/refresh once
  - Success: retry original request
  - Failure: clear auth state, navigate to /login, toast "Your session has expired. Please sign in again."
- Concurrent refresh: use a single shared promise (refreshPromise) — queue callers behind it
- Do not attempt refresh for /api/auth/login, /api/auth/register, /api/auth/refresh itself

    API FETCH WRAPPER (apps/frontend/src/lib/api.ts):
    - Export an `api` object with get(url, opts?), post(url, body?, opts?), patch(url, body?, opts?), delete(url, opts?) methods
    - All calls: credentials: 'include', Content-Type: application/json where applicable
    - Core: a base fetch function that:
      1. Makes the request
      2. If response.status === 401 AND the URL is not /api/auth/login, /api/auth/register, /api/auth/refresh:
         - If refreshPromise is null: set refreshPromise = POST /api/auth/refresh (credentials: 'include')
         - Wait for refreshPromise
         - On success (refresh returned 200): set refreshPromise = null; retry original request once
         - On failure: set refreshPromise = null; call onAuthFailure(); throw error
      3. Return response
    - Export setAuthFailureHandler(handler: () => void): called by AuthContext to wire navigation
    - refreshPromise: Promise<Response> | null = null (module-level — shared across all concurrent callers)
    - The refresh endpoint POST /api/auth/refresh: no body needed (uses cookie)
    - Do not retry infinitely — only one refresh attempt per failed request

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User form input → Zod schema → API | Form data validated client-side with shared schema before API call |
| httpOnly cookie → api.ts fetch | credentials: 'include' sends cookie; never accessed by JS |
| AdminRoute guard | role check in frontend is UX only — backend enforces role with requireAdmin |
| Refresh token response → AuthContext | Auth state cleared if refresh fails; never stored in localStorage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | Client-side AdminRoute | accept | Frontend role check is UX convenience only; backend requireAdmin middleware is the authoritative enforcement; both layers needed |
| T-03-02 | Information Disclosure | Auth state in React context | mitigate | No tokens stored in context or localStorage; only user profile (id, username, role); actual auth via httpOnly cookie |
