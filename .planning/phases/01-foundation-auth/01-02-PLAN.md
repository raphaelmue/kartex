## Prisma schema (established in 01-01) key model signatures
User fields: id, username, passwordHash, role (ADMIN|USER), isActive, createdAt
InviteCode fields: id, code, expiresAt, usedAt (nullable), usedById (nullable), createdAt
RefreshToken fields: id, userId, tokenHash, expiresAt, createdAt

## Key decisions (LOCKED)
- D-01: Admin seeded from ADMIN_USERNAME + ADMIN_PASSWORD env vars on first startup
- D-02: First invite code auto-generated on first run, printed to stdout once
- D-03: Idempotent seed — skip if admin user already exists
- D-06: Hono serves the built React SPA via serveStatic from ./public (catch-all after API routes)
- D-08: Invite codes are single-use — invalidated on use (usedAt set, usedById set)
- D-09: Configurable expiry (default 7 days); admin sets expiryDays when generating
- INFR-03: ALL endpoints except /api/auth/login and /api/auth/refresh require valid JWT
- INFR-04: Rate limiting on login, register, refresh
- INFR-05: CORS restricted to ALLOWED_ORIGIN env var — no wildcard

## jose JWT pattern (from RESEARCH.md)
- Algorithm: HS256
- Access token: 15m expiry, cookie name: access_token
- Refresh token: 30d expiry, cookie name: refresh_token — stored as hash in RefreshToken table (rotation on use)
- Cookie flags: httpOnly: true, sameSite: Strict (NODE_ENV=production), Lax (dev), secure: NODE_ENV=production
- signToken(payload, expiresIn): returns signed JWT string
- verifyToken(token): returns payload or throws

## Hono patterns
- Import Hono from 'hono', serve from '@hono/node-server'
- getCookie / setCookie / deleteCookie from 'hono/cookie'
- cors from 'hono/cors'
- createMiddleware from 'hono/factory'
- c.set('userId', ...) / c.get('userId') for context variables

## Admin route authorization
- /api/admin/* requires: (1) valid access token via authMiddleware, (2) role === 'ADMIN' via requireAdmin
- Non-admin on /api/admin/* → 403 Forbidden
- Admin self-deactivation: PATCH /api/admin/users/:id must reject if the target id === the authenticated admin's id

## Error messages (non-leaking, per CONTEXT.md Claude's discretion)
- Login failure (any reason): "Invalid username or password." — never distinguish user-not-found from wrong-password
- Invalid invite code: "Invalid or expired invite code."
- Username taken: "Username is already taken."
- Unauthorized (no/invalid token): "Unauthorized."
- Forbidden (valid token, wrong role): "Forbidden."

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client HTTP request → Hono route handler | All request data is untrusted user input |
| Cookie store → server | httpOnly cookie prevents JS access; SameSite prevents CSRF |
| Refresh token cookie → DB record | Raw token in cookie; hash in DB — compromise of cookie alone is insufficient |
| Admin endpoints → non-admin JWT | requireAdmin middleware enforces role check |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | POST /api/auth/login | mitigate | bcrypt.compare with 12 rounds; constant-time comparison prevents timing attacks; always return "Invalid username or password" regardless of failure reason |
| T-02-02 | Information Disclosure | Login error messages | mitigate | Non-leaking error: "Invalid username or password." for ALL login failures including user-not-found, wrong-password, deactivated account |

| T-02-04 | Tampering | Refresh token replay | mitigate | Refresh token rotation: old token deleted on use; replayed old token returns 401 |
| T-02-05 | Denial of Service | Auth endpoints | mitigate | rateLimitMiddleware(10, 60_000) applied to /register, /login, /refresh |
