## Key decisions (LOCKED — do not deviate)
- D-04: Yarn workspaces (not pnpm). Root package.json uses `"workspaces": ["apps/*", "packages/*"]`.
- D-05: No Nginx service in docker-compose.yml. Backend port exposed directly for external NPM proxy.
- D-06: Single container — Hono serves the React SPA via serveStatic. Frontend build output copied to apps/backend/public/ in Dockerfile.
- D-07: Production-only docker-compose.yml. No dev docker-compose.
- D-08: Invite codes are single-use (enforced in schema: usedAt field, usedById relation).
- D-09: Invite codes have configurable expiry (expiresAt field).
- INFR-06: All secrets from .env only — no hardcoded values in any source file.

## Yarn version note (from RESEARCH.md)
Use Yarn 1 classic for Docker simplicity. If Yarn Berry is installed globally, add .yarnrc.yml with:
  yarnPath: .yarn/releases/yarn-X.Y.Z.cjs
OR create .yarnrc.yml with:
  nodeLinker: node-modules
to disable PnP. Detect which Yarn version is available and use accordingly.
The `workspace:*` protocol is supported in both Yarn 1 and Yarn Berry.

Note on Yarn 1 classic: the `workspace:*` protocol is only supported in Yarn Berry (2+).
In Yarn 1 classic, use `"*"` for workspace deps and rely on yarn workspaces symlinking.
Detect yarn --version: if < 2, use `"*"` instead of `"workspace:*"`.

## Prisma schema source of truth
The design doc (docs/design.md §6) has the base schema. Adapt it per RESEARCH.md Phase 1 decisions:
- User: id (cuid), username (unique), passwordHash (not hashedPassword, not email — no email field per RESEARCH.md), role (ADMIN|USER), isActive (Boolean default true), createdAt
- InviteCode: id (cuid), code (unique), expiresAt, usedAt (nullable), usedById (nullable FK to User), createdAt
- RefreshToken: id (cuid), userId (FK to User), tokenHash, expiresAt, createdAt
- Keep all other models from design doc exactly: Deck, DeckShare, Card, CardProgress, Media (all needed in later phases)
- Enums: Role (ADMIN USER), Visibility (PRIVATE SHARED PUBLIC), Permission (READ EDIT)
- Schema datasource: postgresql, generator: prisma-client-js with binaryTargets ["native", "linux-musl-openssl-3.0.x"]

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| .env file → Docker Compose | Secrets injected via environment; .env must not be committed |
| Source repo → Docker image | No secrets in Dockerfile, package.json, or schema.prisma |
| External proxy → backend:3000 | Backend port exposed directly; TLS termination at external NPM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | .env secrets | mitigate | .gitignore includes .env; .env.example has only placeholder values; checked in CI via grep |
| T-01-02 | Tampering | docker-compose.yml | mitigate | All secret refs use ${VAR} syntax; grep gate: no hardcoded JWT_SECRET or DB_PASSWORD values |
| T-01-03 | Tampering | Prisma schema | accept | Schema is read-only at runtime; Prisma client generated at build time; no runtime schema writes |
| T-01-04 | Elevation of Privilege | Prisma binary targets | mitigate | binaryTargets includes linux-musl-openssl-3.0.x for Alpine; prevents binary mismatch errors |
| T-01-SC | Tampering | npm/yarn installs | mitigate | yarn install --frozen-lockfile in Dockerfile; yarn.lock committed; no post-install scripts for core packages |
</threat_model>
