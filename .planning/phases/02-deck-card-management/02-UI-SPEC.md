| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tag chip gap, icon-text gap within badges |
| sm | 8px | Button group gaps, compact form field spacing |

| lg | 24px | Card grid gap, section heading bottom margin |

- Main content area: p-8 (32px) padding on all sides (established in Phase 1 AppShell — do not change)

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|

Notes:

## Color

All values are CSS custom properties declared in `apps/frontend/src/index.css`. Light and dark mode tokens are already defined.

| Role | CSS Variable | Resolved (Light) | Usage |
|------|-------------|------------------|-------|
| Dominant (60%) | `--background` | hsl(0 0% 98%) — near-white | Main content area background |
| Secondary (30%) | `--card` / `--secondary` | hsl(0 0% 100%) / hsl(0 0% 96%) | Deck grid tiles, sidebar, card table rows |
| Accent (10%) | `--accent` / `--primary` | hsl(0 0% 96%) / hsl(0 0% 9%) | See accent reserved list below |
| Destructive | `--destructive` | hsl(0 84% 60%) | Delete deck button, delete card button only |

**Accent reserved for (explicit list):**
- Active sidebar nav item background (`bg-accent` — established Phase 1 pattern)
- Primary action buttons: "New Deck" CTA, "Add Card" button, "Save Card" in modal (`bg-primary text-primary-foreground`)
- Focused/hovered interactive states on nav items (`hover:bg-accent/50`)

**Visibility badge color semantics** (from CONTEXT.md specifics — distinct colors per state):
- Private: `bg-muted text-muted-foreground` — muted/neutral
- Shared: `bg-blue-100 text-blue-800` — blue (matches InviteStatusBadge Active pattern in AdminPage)
- Public: `bg-green-100 text-green-800` — green (matches AdminPage StatusBadge Active pattern)

Badge structure (follow AdminPage InviteStatusBadge pattern exactly):
```
inline-flex items-center rounded-full px-2 py-0.5 text-xs font-medium {color classes}
```

**Destructive confirmation:** Inline in-table confirmation (same pattern as AdminPage — not a separate modal):
- Show "Are you sure?" text + "Yes, delete" (destructive) + "Cancel" (outline) buttons inline
- Use `role="alert"` on the confirmation span, support Escape key to cancel
- Applied to: delete deck action, delete card action

### CardEditorModal — Create / Edit Card

**Component:** shadcn `Dialog`
**Width:** `max-w-2xl` (672px) — wide enough for two textarea/preview areas stacked vertically
**Trigger:** "Add Card" button (create) or "Edit" button in card table row (edit, pre-filled)

| Element | Component | Specification |
|---------|-----------|---------------|
| Modal title | `DialogTitle` | "Add Card" or "Edit Card" |
| Front content section | shadcn `Tabs` | Tab 1: "Edit" (textarea), Tab 2: "Preview" (KartexRenderer) |
| Front textarea | `<textarea>` | 8 rows, `placeholder="Front side content (Markdown)"`, `font-mono text-sm` |
| Front preview | `KartexRenderer` | `min-h-[192px]` (matches ~8 rows), `prose prose-sm max-w-none dark:prose-invert` |
| Back content section | shadcn `Tabs` | Same structure as front — independent tab state |
| Back textarea | `<textarea>` | 8 rows, `placeholder="Back side content (Markdown)"`, `font-mono text-sm` |
| Back preview | `KartexRenderer` | Same as front preview |
| Tags field | `Input` | `placeholder="react, typescript, algorithms"` — comma-separated freeform text |
| Tags label | `Label` | "Tags (comma-separated, optional)" |
| Cancel button | `Button variant="outline"` | "Cancel" — closes dialog, discards changes |
| Save button | `Button variant="default"` | "Save Card" |
| Validation errors | `text-sm text-destructive` | Shown below front/back textareas if empty on submit |

**Tab toggle interaction:**
- Each content section (front, back) has independent `defaultValue="edit"` on its `Tabs` component
- Active tab: `bg-background` with bottom border indicator (shadcn Tabs default style)
- Tab keyboard navigation: left/right arrow keys (Radix UI default)

**Tag input UX decision (Claude's Discretion):**
Comma-separated freeform text input. No chip-parsing in the UI — chips appear only in the read-only card table. Split happens at form submit: `tagInput.split(',').map(t => t.trim()).filter(Boolean)`. This is the simpler Phase 2 approach. Phase 3+ can upgrade to a chip input component without API changes.

## Interaction Contracts

### Modal open/close
- Open: triggered by button click; focus moves to first interactive element inside Dialog (Radix default)
- Close: Escape key OR Cancel button OR clicking outside (Radix `DialogContent` default `onInteractOutside` behavior — keep default)
- After close: focus returns to the trigger button

### CRUD feedback (Sonner toasts)
All mutations use the existing `sonner` toast setup. Specific messages defined in Copywriting Contract.

### Destructive confirmation pattern (established from AdminPage)
- Step 1: Click "Delete" button → button replaced inline by "Are you sure?" + "Yes, delete" (destructive) + "Cancel" (outline)
- Step 2a: Click "Yes, delete" → execute delete, show success toast, refresh list
- Step 2b: Click "Cancel" or press Escape → revert to initial "Delete" button state
- Applied to: delete deck (on /decks tile), delete card (in /decks/:id table)

### Loading states
- Page-level data fetch: no skeleton; show nothing (empty) until data arrives — consistent with AdminPage pattern
- Submit buttons: disabled + label changes to "Saving..." during inflight mutation

### Deck list refresh
After any deck create/edit/delete, call `fetchDecks()` to re-fetch from server (established AdminPage pattern). Do not optimistically update local state.

### Card list refresh
After any card create/edit/delete, call `fetchCards()` to re-fetch from server.
