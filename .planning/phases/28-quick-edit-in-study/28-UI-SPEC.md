# Phase 28 — UI Design Contract

> Visual and interaction contract for the study-session quick-edit menu.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase adds exactly one new visual element — a 3-dot
> overflow menu (`StudyCardMenu`) in the study session's progress row — plus
> its two actions ("Edit this card" reusing the existing `CardEditorModal`,
> and "Jump to deck" as a plain navigation). No new pages, no new modals, no
> new form fields. All contracts below apply to `StudyCardMenu.tsx` and its
> integration point in `StudySessionPage.tsx`'s `SessionRunner`.

## Component Contract: `StudyCardMenu`

This is the primary contract for this phase.

### Trigger

**Placement (D-01):** Last child in the existing progress row
(`<div className="flex items-center gap-2 mb-3 shrink-0">` in
`SessionRunner`, currently containing `SessionProgress` + deck `Badge` +
optional mode `Badge`). Add `className="ml-auto"` to the trigger `Button`
so it anchors to the right edge of the row regardless of how many badges
precede it (deck badge is always present; mode badge is conditional).

**Conditional render (SEDIT-01, SEDIT-04):** The entire `StudyCardMenu`
component — trigger included — is omitted from the DOM when
`currentCard.canEdit === false`. Never render-then-disable.

```tsx
{currentCard.canEdit && (
  <StudyCardMenu onEdit={handleOpenEditor} onJumpToDeck={handleJumpToDeck} />
)}
```

**Trigger markup:**
```tsx
<DropdownMenuTrigger asChild>
  <Button size="sm" variant="ghost" className="ml-auto" aria-label={t('study.cardMenuAriaLabel')}>
    <MoreVertical className="h-4 w-4" />
  </Button>
</DropdownMenuTrigger>
```

- Icon: `MoreVertical`, 16px × 16px (`h-4 w-4`) — matches `DecksPage.tsx`
  exactly (not the `MoreHorizontal` icon suggested in the original folded
  todo; codebase precedent wins per RESEARCH.md).
- Button variant: `ghost`, size: `sm` — identical to every other
  icon-only overflow trigger in the app (`DecksPage.tsx`, `AdminPage.tsx`).
- No `e.stopPropagation()` on click handlers anywhere in this component.
  Placement in the progress row (D-01) is structurally outside `CardFlip`'s
  click zone, so the flip-on-click guard is unnecessary. Do not add a
  defensive no-op guard "just in case" (RESEARCH.md anti-pattern) — if this
  ever needs revisiting, it means the placement itself changed and the click
  zone must be re-verified at that time.

### Menu content

```tsx
<DropdownMenuContent align="end">
  <DropdownMenuItem onClick={onEdit}>{t('study.editThisCard')}</DropdownMenuItem>
  <DropdownMenuItem onClick={onJumpToDeck}>{t('study.jumpToDeck')}</DropdownMenuItem>
</DropdownMenuContent>
```

- Exactly two items, in this order: "Edit this card" first, "Jump to deck"
  second (matches SEDIT-02/SEDIT-03 requirement order and the original
  todo's stated priority).
- `align="end"` — right-aligns the dropdown content to the trigger, since
  the trigger sits at the row's right edge (`ml-auto`).
- Neither item uses `text-destructive` styling — both are neutral,
  non-destructive actions (D-06 confirms no confirmation dialog for
  navigation either).
- No leading icons on menu items — matches `DecksPage.tsx`'s
  edit/delete items (text-only), keeps the two-item menu visually simple.

### Behavior states

| State | Trigger visibility | Notes |
|-------|--------------------|----|
| `currentCard.canEdit === true` | Visible on both card faces (D-02) | Menu is unaffected by flip state since it lives outside `CardFlip` |
| `currentCard.canEdit === false` | Absent from DOM entirely (SEDIT-04) | Not `disabled`, not hidden via CSS — not rendered |
| Any study mode, including Exam mode (D-05) | Same visibility rule applies | No mode-based suppression anywhere in this component |

### Post-edit visual behavior (D-03)

No transient visual indicator (no flash, no toast, no "updated" badge) is
introduced when a card is saved via "Edit this card." The displayed card
content updates silently and immediately once `CardEditorModal` closes —
consistent with the project's existing pattern where `CardEditorModal`'s
own success path (used in `DeckDetailPage.tsx`) does not show a toast
either, only closes the dialog. Do not add a new toast/animation for this
phase; it was not requested and would be scope creep beyond SEDIT-02.

### Jump to deck (D-06)

`onJumpToDeck` calls `navigate(`/decks/${currentCard.deckId}`)` directly —
no confirmation dialog, no `AlertDialog`. This is a plain navigation, not a
destructive action.

| Element | Copy | Localized? |
|---------|------|------------|
| Trigger aria-label | "More actions" (`study.cardMenuAriaLabel`) | Yes — new i18n key, en.json + de.json |
| Menu item: edit | "Edit this card" (`study.editThisCard`) | Yes — new i18n key, en.json + de.json |
| Menu item: jump | "Jump to deck" (`study.jumpToDeck`) | Yes — new i18n key, en.json + de.json |
| Primary CTA | Not applicable — this phase adds a menu, not a page-level CTA. The two menu items above are the phase's only user-initiated actions. | — |
| Empty state | Not applicable — no new list/data view in this phase | — |
| Error state | Not applicable — no new error surface. If save fails inside `CardEditorModal`, it already has its own existing error handling (unchanged by this phase) | — |
| Destructive confirmation | None — neither "Edit this card" nor "Jump to deck" is destructive (D-06 explicitly rules out a confirmation dialog for navigation) | — |

**i18n key placement:** All three new keys go in the existing `study`
namespace in both `en.json` and `de.json`, added in the same commit (per
STATE.md `10-05` pitfall-prevention pattern — never let one locale file
lag behind). Naming follows the existing `study.deckBadgeAriaLabel`
convention (aria-label keys carry an `AriaLabel` suffix within the `study`
namespace, not the separate `a11y` namespace — `decks.moreActions` is the
closer precedent for an overflow-trigger label than any `a11y.*` key).

```json
// en.json, inside "study": { ... }
"cardMenuAriaLabel": "More actions",
"editThisCard": "Edit this card",
"jumpToDeck": "Jump to deck"
```

```json
// de.json, inside "study": { ... } — suggested translations, confirm with project convention
"cardMenuAriaLabel": "Weitere Aktionen",
"editThisCard": "Karte bearbeiten",
"jumpToDeck": "Zum Stapel springen"
```
