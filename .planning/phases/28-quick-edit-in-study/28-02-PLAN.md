<objective>
Add the quick-edit menu to the study session: a 3-dot overflow menu (`StudyCardMenu`) in the progress row that lets owner/EDIT users edit the current card inline (reusing `CardEditorModal`) or jump to its deck — never leaving the session. Covers SEDIT-01 through SEDIT-04. Pure wiring/composition; no new capability.

Purpose: complete the user-facing loop for the phase goal — an editor can correct a card mid-session (content updates in place, session continues) or jump to the deck, and non-editors never see the menu at all.

Output: new `StudyCardMenu.tsx`, an `onCardUpdated` callback on `CardEditorModal`, integration into `SessionRunner`/`StudySessionPage`, three i18n keys in both locales, and frontend tests covering the four requirements.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (StudyCardMenu render) → server flag | The menu's visibility is decided from the server-supplied `currentCard.canEdit`; the client never computes permission itself. |
| client (edit save) → API PATCH | The real mutation crosses here; `PATCH /api/decks/:deckId/cards/:cardId` re-derives access independently (unchanged, out of this phase's scope). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-04 | Elevation of Privilege | StudyCardMenu visibility gate | medium | mitigate | Render is gated only on the server-computed `currentCard.canEdit`; the client never infers permission from local data. The save still passes through the PATCH route's independent `getDeckAccess` check, so a tampered/stale flag cannot elevate — it can only trigger a 403 toast. |
| T-28-05 | Information Disclosure | stale canEdit after mid-session share revocation | low | accept | A share revoked mid-session leaves a stale editable menu in an open tab; the save 403s server-side. No data is exposed. Purely a cosmetic UX edge — accepted per RESEARCH.md Open Question 1 / Pitfall 5. |
| T-28-06 | Tampering | CardEditorModal PATCH body | low | mitigate | Unchanged input surface — existing `UpdateCardSchema` (Zod) validates the PATCH body; this phase adds no new input fields. |
