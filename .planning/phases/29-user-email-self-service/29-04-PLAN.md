<objective>
Build the admin half of email self-service: an "Edit email" action in each user row's existing DropdownMenu that opens a single shared Dialog with an RHF+Zod email form submitting to the reused PATCH /api/admin/users/:id endpoint.

Purpose: Admins must be able to set or correct any user's email (success criterion 5, EMAIL-11) — important because a user with no email cannot self-reset a password. The Dialog reuses the single-shared-instance state pattern already established by the delete-user AlertDialog, and the same EMAIL_TAKEN/inline-error contract as the Settings form.
Output: "Edit email" DropdownMenuItem (first) + editEmailTargetId-controlled Dialog + submit handler in AdminPage.tsx, plus new RTL test cases in AdminPage.test.tsx.
</objective>
