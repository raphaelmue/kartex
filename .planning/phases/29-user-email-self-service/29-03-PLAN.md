<objective>
Build the Settings-page half of email self-service: a new first Email Card with a react-hook-form + zodResolver form, and the amber no-email Alert banner above it.

Purpose: This is the primary user-facing surface (success criteria 2, 3, 4). It reuses the ForgotPasswordPage RHF+Zod+shadcn Form pattern exactly, and deliberately does NOT copy the optimistic handleModeChange pattern — a 409 conflict is an expected, common outcome for email edits, so the form waits for server confirmation before touching AuthContext.
Output: Email Card + no-email Alert in SettingsPage.tsx, plus new RTL test cases in the existing SettingsPage.test.tsx.
</objective>
