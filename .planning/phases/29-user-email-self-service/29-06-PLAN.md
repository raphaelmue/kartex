<objective>
Close the truth-6 regression from 29-VERIFICATION.md: `POST /api/auth/login` and `POST /api/auth/refresh` omit the `email` field that `GET /api/auth/me` and the admin endpoints already return. Because AuthContext hydrates the user object directly from the login/refresh response (and only re-fetches `/me` once, on top-level app mount), any user who already has an email set sees `user.email === undefined` right after login — producing a false "No email address set" warning and an empty pre-filled email input in Settings until a full page reload.

Purpose: Restore the phase's stated user-facing behavior ("...see a warning when no email is set") for the common already-logged-in-with-email case, and add a regression guard so this omission class (previously fixed once for `studyMode` in phase 11, commit fc7b3b9) cannot silently recur.

Output: login/refresh responses include `email`; AuthContext's User type is single-sourced from shared's UserResponse; a real route-level test asserts the response shape.
</objective>
