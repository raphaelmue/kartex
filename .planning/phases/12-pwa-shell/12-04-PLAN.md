<task type="auto">
  <name>Task 2: Smoke-test HTTP headers against running Hono server (PWA-04 and PWA-05)</name>
  <read_first>
    - apps/backend/src/index.ts (confirm the server start command and default port — PORT env defaults to 3000; the server reads ./public relative to cwd)
    - apps/backend/package.json (confirm start script: "node dist/index.js"; confirm build script: "tsc")
    - .planning/phases/12-pwa-shell/12-RESEARCH.md (Validation Architecture: curl commands for PWA-04 and PWA-05)
  </read_first>
  <action>
    Step 1 — Build and start the backend in the background (pointing it at the Vite-built frontend):
      yarn workspace @kartex/backend build
      Start-Process -NoNewWindow node -ArgumentList "apps/backend/dist/index.js" -WorkingDirectory (Get-Location).Path

    Allow 2 seconds for the server to start, then run header checks via Invoke-WebRequest or curl.

    Step 2 — Check COOP/COEP headers on GET / (PWA-04):
      curl -I http://localhost:3000/ 2>&1 | Select-String -Pattern "cross-origin"
      Expected output must contain:
        cross-origin-opener-policy: same-origin
        cross-origin-embedder-policy: require-corp

    Step 3 — Check Cache-Control: no-store on GET /sw.js (PWA-05):
      curl -I http://localhost:3000/sw.js 2>&1 | Select-String -Pattern "cache-control"
      Expected output must contain:
        cache-control: no-store

    Step 4 — Check Cache-Control: no-store on GET /workbox-*.js (PWA-05):
      Find the actual workbox filename in apps/backend/public/ (e.g. workbox-abc12345.js), then:
      curl -I http://localhost:3000/workbox-abc12345.js 2>&1 | Select-String -Pattern "cache-control"
      Expected output must contain:
        cache-control: no-store

    Step 5 — Stop the server after checks complete.

    If curl is not available in PowerShell, use: Invoke-WebRequest -Method Head -Uri http://localhost:3000/ | Select-Object -ExpandProperty Headers

    Record all curl output for the SUMMARY.md.
  </action>
  <verify>
    <automated>
      curl -I http://localhost:3000/ 2>&1 | Select-String "cross-origin-opener-policy"
    </automated>
  </verify>
  <acceptance_criteria>

    - GET http://localhost:3000/ response headers contain: cross-origin-embedder-policy: require-corp
    - GET http://localhost:3000/sw.js response headers contain: cache-control: no-store
    - GET http://localhost:3000/sw.js response status is 200 (not 404 — confirms sw.js was found in ./public/sw.js)
    - GET http://localhost:3000/workbox-[hash].js response headers contain: cache-control: no-store
    - GET http://localhost:3000/workbox-[hash].js response status is 200

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → SW → /api/* | NetworkOnly must prevent any API response from being served from SW cache |
| Browser → Hono | COOP/COEP headers must be present on all responses including document navigation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-07 | Information Disclosure | SW intercepting /api/* and returning stale auth state | mitigate | Verified in Task 1: sw.js precache manifest excludes /api/ paths; Task 3 human check confirms SW registers correctly |
| T-12-08 | Tampering | COEP blocking legitimate self-hosted media (/api/media/*) | accept | Self-hosted media served from same origin — no cross-origin resource loading. KaTeX fonts bundled in npm package, served from same origin. Typst WASM bundled. No external CDN resources. Risk is low. |
| T-12-09 | Tampering | Old sw.js version served after redeployment | mitigate | Verified in Task 2: /sw.js Cache-Control: no-store confirmed via curl; browser will always fetch fresh sw.js on navigation |
</threat_model>
