## Spacing Scale

All values are multiples of 4. Follows Tailwind's default scale as used across existing pages.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap (`gap-1`), tag chip inner padding |
| sm | 8px | Button/badge inner padding, row gap in compact areas |
| md | 16px | Default spacing — CardContent padding, form row gaps |
| lg | 24px | Section separation — `mb-6`, `gap-6` card grid |
| xl | 32px | Page-level section breaks — `mb-8` (dashboard sections) |
| 2xl | 48px | Generous vertical padding — `py-12` used in empty states |
| 3xl | 64px | Full empty-state centering — `py-16` established pattern |

Exceptions:
- **Badge chip vertical padding: 2px (`py-0.5`)** — established pattern inherited from `VisibilityBadge` (already used in `DecksPage.tsx` and `DeckDetailPage.tsx`). Badge height is determined by line-height × font-size, so 2px vertical padding keeps the pill proportionally tight. All new badge/pill components (PermissionBadge, visibility chips) follow this same 2px exception.

## Typography

Established across the existing codebase; Phase 6 does not introduce new type styles.

**Weights in use:** 2 — `400` (normal) for all body/meta text; `700` (bold) for all headings and card titles.

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|---------|
| Body | 14px | 400 | 1.5 | `text-sm` |
| Muted body / attribution | 14px | 400 | 1.5 | `text-sm text-muted-foreground` |
| Micro / meta / badge | 12px | 400 | 1.5 | `text-xs` or `text-xs text-muted-foreground` |
| Heading (page + section + card title) | 18–24px | 700 | 1.25 | `text-lg font-bold` / `text-2xl font-bold` |

## Color

The design system is a **neutral grayscale palette** using CSS custom properties. All role assignments below reference semantic token names — never hardcode hex values.

| Role | CSS Token | Light Value | Usage |
|------|-----------|-------------|-------|
| Dominant (60%) | `--background` | `hsl(0 0% 98%)` ≈ #fafafa | Page background, main content area |
| Secondary (30%) | `--card` + `--muted` | #fff / `hsl(0 0% 96%)` | Card surfaces, sidebar, input fills |
| Primary / Accent (10%) | `--primary` | `hsl(0 0% 9%)` ≈ #171717 | Main CTA buttons, active nav, page headings |
| Muted text | `--muted-foreground` | `hsl(0 0% 45%)` ≈ #737373 | Descriptions, attribution text, empty states |
| Border | `--border` | `hsl(0 0% 90%)` ≈ #e5e5e5 | Card borders, table rows, section dividers |
| Destructive | `--destructive` | `hsl(0 84% 60%)` ≈ #e53e3e | Destructive buttons only (Delete, Revoke) |

**Accent reserved for:** Primary CTA buttons (filled black), active nav item highlight, `ring` focus outline. Never applied to headings, body text, or generic containers.

### Status / semantic colors (established pattern — safe to extend)

`VisibilityBadge` already uses non-token Tailwind colors (`bg-green-100`, `bg-blue-100`). Phase 6 extends the same pattern for permission badges:

| Badge | Classes | Semantics |
|-------|---------|-----------|
| Visibility: Private | `bg-muted text-muted-foreground` | Token-based — neutral |
| Visibility: Shared | `bg-blue-100 text-blue-800` | Tailwind — blue |
| Visibility: Public | `bg-green-100 text-green-800` | Tailwind — green |
| Permission: READ | `bg-secondary text-secondary-foreground` | Token-based — neutral/gray |
| Permission: EDIT | `bg-blue-100 text-blue-800` | Tailwind — blue (same as Shared) |

## Surface Contracts

Phase 6 adds one new page and extends two existing pages. Each surface is specified below.

### Surface 1 — ExplorePage (`/explore`)

**Primary focal point:** The card grid itself — specifically each deck card's title and Fork CTA. The grid is the page's entire purpose; heading is orientation only.

**Layout:** Full-width page matching `/decks` pattern. `max-w` unconstrained, `p-8` from AppShell.

```
h2: "Explore"                              (text-2xl font-bold mb-6)

[Empty state — shown when decks.length === 0]
  Compass icon  h-10 w-10 text-muted-foreground
  "No public decks yet"                    (text-sm font-bold)
  "Decks made public will appear here."    (text-sm text-muted-foreground)

[Grid — shown when decks.length > 0]
  grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6

  Card (shadcn Card — matches DecksPage tile shape)
  ┌────────────────────────────────────────┐
  │ CardHeader                             │
  │   CardTitle: "Deck Name"    line-clamp-2 text-lg font-bold
  │   CardDescription: "desc…" line-clamp-2
  │                                        │
  │ CardContent                            │
  │   p "by username"   text-sm text-muted-foreground
  │   p "N cards"       text-sm text-muted-foreground
  │                                        │
  │ CardFooter                             │
  │   [GitFork icon] Fork Deck   Button size=sm variant=outline
  └────────────────────────────────────────┘
```

**Loading state:** `<p className="text-sm text-muted-foreground">Loading…</p>` centered (matches DashboardPage pattern).

**Fork interaction:**
- Button shows loading state (disabled) while POST /api/decks/:id/fork is in-flight.
- On success: sonner toast with message + "View deck" action button navigates to `/decks/[forkedId]`.
- On failure: sonner `toast.error(...)` with generic message. Button re-enabled.

### Surface 2 — DeckDetailPage sharing section (owner view)

**Primary focal point:** The "Add User" form row — it is the primary action in this section. The share list table below is reference/management, not the primary CTA.

**Placement:** Below the existing cards table. Separated by a `<div className="mt-8 pt-6 border-t border-border">` section divider.

**Visibility rule:** Section renders only when `deck.ownerId === currentUser.id` OR `userPermission === 'MANAGE'`. Hidden for READ/EDIT users.

```
<div className="mt-8 pt-6 border-t border-border">
  h3: "Share this deck"                   (text-lg font-semibold mb-4)

  [Add share form — inline row]
  <div className="flex items-center gap-2 mb-6">
    Input placeholder="Username"          (flex-1 max-w-xs)
    Select: Read / Edit / Manage          (w-36)
    Button: "Add User"                    (size=sm)

      User: username                      (text-sm)

      Actions: [Permission Select inline] + [Revoke Access Button destructive size=sm]

  [Empty state — shown when shares.length === 0]
  <p className="text-sm text-muted-foreground">
    "Not shared with anyone yet."
  </p>
</div>
```

## Interaction Patterns

### Permission Select (inline in share table row)

Uses the existing `select` shadcn component. Options: `READ`, `EDIT`, `MANAGE`. On change, fires PATCH /api/decks/:id/shares/:userId immediately (optimistic update on success, revert on error).

### Revoke button

Uses `Button variant="destructive" size="sm"`. No confirm dialog — revoke is recoverable (owner can re-add the user). This deviates from the deck-delete confirm pattern intentionally (shares are lower-stakes than deck deletion).

If revoke is needed for the last share and deck visibility is SHARED, the deck visibility stays SHARED — no auto-revert (per Research open question 1 recommendation).

### Fork button state

During in-flight POST:
```tsx
<Button size="sm" variant="outline" disabled>
  <GitFork className="h-4 w-4 mr-1" />
  Forking…
</Button>
```
