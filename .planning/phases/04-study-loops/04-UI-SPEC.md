## Spacing Scale

Declared values (multiples of 4, mapped to Tailwind tokens):

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, inline padding |
| sm | 8px | `gap-2`, `p-2` | Compact element spacing, button icon gap |
| md | 16px | `gap-4`, `p-4` | Default element spacing, card padding |
| lg | 24px | `gap-6`, `p-6` | Section padding, card face internal padding |

## Typography

Two weights only: 400 (regular) for body/caption/label, 600 (semibold) for heading/display.

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|---------|
| Caption | 12px | 400 (regular) | 1.4 | `text-xs font-normal` |
| Body | 14px | 400 (regular) | 1.5 | `text-sm font-normal` |
| Heading | 20px | 600 (semibold) | 1.3 | `text-xl font-semibold` |
| Display | 48px | 600 (semibold) | 1.1 | `text-5xl font-semibold` |

**Display role** is used exclusively for the dashboard due-count hero number (D-07: "X cards due today" — the number `X` itself).

**Heading role** is used for page-level h2 headings and modal/section titles.

**Caption role** is used for uppercase tracking labels, keyboard hints, muted supporting text, and stat chip labels.

**No custom font loaded** — system font stack matches established project pattern (no `@font-face` in `index.css`).

#### 2b. Card Face — Front State

Layout: vertically and horizontally centered within the content area. Card scene wrapper: `flex flex-col items-center justify-center flex-1 min-h-0 py-8`.

Card scene (3D context):
```
<div style={{ perspective: '1000px' }} className="w-full max-w-2xl mx-auto">
  <div  ← card-body: transform-style preserve-3d, transition duration-300
    ...
  >
    [FRONT FACE]
    [BACK FACE — hidden]
  </div>
</div>
```

**Card face dimensions:**
- Width: `w-full max-w-2xl` (672px max, fluid below)
- Min height: `min-h-[320px]` on mobile (`sm:min-h-[400px]` on desktop)
- Border: `border border-border rounded-lg` (`border-radius: calc(0.5rem - 2px)` = `rounded-md` per theme)
- Shadow: `shadow-md` (medium elevation — heavier than list cards to convey focus)
- Background: `bg-card` on both faces
- Cursor: `cursor-pointer` on front face to hint clickability

Front face content layout:
```
[ Card face — front ]
  padding: p-8 (32px all sides)
  [ "Front" label ]     ← text-xs text-muted-foreground font-normal uppercase tracking-wide, mb-4
  [ KartexRenderer ]    ← prose-sm max-w-none (inherits existing KartexRenderer class)
  [ ── ]                ← hr border-border mt-8
  [ Click or press Space to reveal ]  ← text-xs text-muted-foreground text-center mt-4 select-none
```

**Progress indicator:** Above the card scene, `text-sm text-muted-foreground text-center mb-4`:
`Card 3 of 12` (format: "Card {current} of {total}")

**Exam timer (when mode=exam):** Appears in the top-right corner of the session layout as a fixed badge:
```
[ Clock icon ]  [ MM:SS ]
```
Rendered as: `flex items-center gap-1 text-sm font-mono tabular-nums`. Normal state: `text-foreground`. Warning state (≤60 seconds): `text-orange-500`. Critical state (≤10 seconds): `text-red-500 animate-pulse`.

#### 2c. Card Face — Back State (after flip)

Same card scene, now showing the back face (rotated 180deg). Rating buttons revealed below the card.

Back face content layout:
```
[ Card face — back ]
  padding: p-8
  [ "Front" label ]     ← text-xs text-muted-foreground font-normal uppercase, mb-2
  [ KartexRenderer for frontContent ]  ← dimmer — wrap in opacity-60
  [ ── ]                ← hr border-border my-4
  [ "Back" label ]      ← text-xs text-muted-foreground font-normal uppercase, mb-2
  [ KartexRenderer for backContent ]   ← full opacity
```

**Rating buttons (D-03, D-04 — locked):** Revealed only after flip. Layout: `flex gap-2 mt-6 w-full max-w-2xl mx-auto`.

Each button: `flex-1 min-h-[44px] rounded-md text-white font-semibold text-sm transition-colors`:

| Button | Label | Keyboard | Tailwind classes |
|--------|-------|----------|-----------------|
| Again | `Again` + `1` hint | key `1` | `bg-red-500 hover:bg-red-600` |
| Hard | `Hard` + `2` hint | key `2` | `bg-orange-500 hover:bg-orange-600` |
| Good | `Good` + `3` hint | key `3` | `bg-green-500 hover:bg-green-600` |
| Easy | `Easy` + `4` hint | key `4` | `bg-blue-500 hover:bg-blue-600` |

Keyboard hint rendering inside each button:
```
[ Again ]
[  (1)  ]
```
Two lines: label in `text-sm font-semibold`, shortcut in `text-xs opacity-70` below. Button height auto-expands from `min-h-[44px]` with `py-2 px-3`.

Buttons are `disabled` and `opacity-50 pointer-events-none` during the 300ms flip animation (`isFlipping` state).

#### 2d. CSS 3D Flip Animation Spec (D-02 — locked)

Duration: 300ms, timing: `ease`.

Required CSS properties (applied via Tailwind arbitrary values + inline style):

```
Card scene wrapper:    style={{ perspective: '1000px' }}
Card body:             className="relative transition-transform duration-300"
                       style={{ transformStyle: 'preserve-3d' }}
                       When flipped: style={{ transform: 'rotateY(180deg)', transformStyle: 'preserve-3d' }}
Front face:            className="backface-hidden"  (custom utility — see below)
                       style={{ backfaceVisibility: 'hidden', WebkitBackfaceVisibility: 'hidden' }}
Back face:             same + style={{ transform: 'rotateY(180deg)' }}
                       position: absolute inset-0
```

**Critical constraints (from RESEARCH.md Pitfall 2 and 3):**
1. Both faces MUST have `backfaceVisibility: 'hidden'` AND `WebkitBackfaceVisibility: 'hidden'` (inline style, not just Tailwind class — vendor prefix required for Safari/iOS).
2. No `overflow: hidden` on any ancestor of the card body element. The card scene wrapper must use `overflow: visible`.
3. `transformStyle: 'preserve-3d'` applied as inline style on the card body (not on the outer flex container).
4. Do NOT apply `transform-style` to a Tailwind flex container — keep the 3D context on the inner card-body div only.

Content switch timing: the back face content (`backContent`) renders always but is hidden by `backface-visibility`. No JS setTimeout needed to swap content — both faces exist in DOM simultaneously.

#### 2e. Session Completion Screen (discretion)

Shown when `currentIndex >= cards.length` (all cards rated). Replaces the card area. Full-page centered layout within AppShell.

Layout: `flex flex-col items-center justify-center flex-1 text-center py-16 gap-6 max-w-md mx-auto`.

```
[ Trophy icon ]                         ← lucide-react Trophy, h-12 w-12 text-yellow-500
[ Session complete! ]                   ← text-xl font-semibold
[ You reviewed {N} cards ]              ← text-sm text-muted-foreground (SR/Deck mode only)
  or
[ You reviewed {N} cards in {M}m {S}s ] ← exam mode: includes elapsed time

[ Stats row ]                           ← flex gap-4 justify-center
  [ Again: N ]  [ Hard: N ]  [ Good: N ]  [ Easy: N ]
  ← each: text-sm, colored to match rating button colors

[ Return to Dashboard ]                 ← Button variant="default" size="lg" w-full mt-4, navigates to /dashboard
[ Restart Session ]                     ← Button variant="outline" size="sm" w-full, restarts session (same mode/deck)
```

**Exam mode timer-expired state (D-05 — locked):** When timer hits zero, a banner appears above the current card:

```
[ ⏰ Time's up! ]  [ Rate this card to finish ]
```
`bg-orange-50 border border-orange-200 rounded-md p-3 mb-4 flex items-center gap-2 text-sm text-orange-800`

The current card remains interactive. Rating it triggers normal session advance. If it was the last card, completion screen appears immediately.

#### 2f. Session Exit Handling (discretion)

**Decision (Claude's Discretion):** In-progress SM-2 ratings already submitted (POST /api/study/rate called per card after rating) are persisted permanently. Cards not yet reached in the queue are unaffected. There is no "discard on exit" — each card rating is immediately persisted when the user presses 1–4.

**Early exit UI:** A "Leave Session" button appears in the top-left of the session layout (below the AppShell header): `Button variant="ghost" size="sm"` with `← Leave Session` label and `ArrowLeft` icon. Clicking navigates back with `navigate(-1)` (no confirmation dialog — since ratings are already saved per card, there is nothing to "lose").

**No `beforeunload` handler** — the immediate-persistence model means navigation away never discards data.

## Keyboard Contract

| Key | Context | Action |
|-----|---------|--------|
| Space | Card showing front face | Flip card |
| `1` | Card showing back face | Rate "Again" (SM-2 quality 0) |
| `2` | Card showing back face | Rate "Hard" (SM-2 quality 3) |
| `3` | Card showing back face | Rate "Good" (SM-2 quality 4) |
| `4` | Card showing back face | Rate "Easy" (SM-2 quality 5) |

Guards: Space does nothing when face is "back" or during flip animation. Keys 1–4 do nothing when face is "front" or during flip animation. All keyboard handlers attached to `window` via `useEffect`, cleaned up on unmount. Keys 1–4 must be guarded by `face === 'back'` to prevent accidental pre-flip ratings (RESEARCH.md Pitfall 8).
