<objective>
Make the `.kartex` parser honor the optional `id:` card field (IMP-07) and document the field in the format reference.

Purpose: Phase 16 import-update matches cards between an uploaded file and existing deck rows by `kartexId`. The parser must expose the `id` value from each card block so the import flow can store it in `Card.kartexId` (per Plan 01 schema). Backward compatibility is non-negotiable — existing `.kartex` files (which contain no `id:` field) must continue to import unchanged.

Output:
- `parseFields()` and `parseCardBlock()` updates so the result object carries an optional `id`
- New vitest unit tests asserting id-present, id-absent (backward compat), and duplicate-id (parser-tolerated) behaviors
- Updated `docs/kartex-format.md` documenting the optional `id:` field

This plan does NOT touch the Prisma schema, the rate endpoint, or the import route (Phase 16). It only changes the shared parser library and the format spec.
</objective>
