<objective>
Deliver the backend tier: persist `thinkingTimeMs` on rating, add the StudySession lifecycle endpoints (start/complete), and extend `GET /api/stats/summary` with per-deck average flip time and the recent-sessions list.

Purpose: The server is the source of truth for computed values (T-4-03 established pattern). `thinkingTimeMs` is client-measured but stored verbatim (a display stat, not a security value); session `durationSeconds` is computed server-side from the persisted `startedAt`→`completedAt` timestamps so a tampered client cannot inflate it. Every StudySession-deck association is authorization-checked against deck ownership/active-share before insert.
Output: extended `study.ts` (rate + two session routes) and `stats.ts` (summary aggregation), plus behavioral-contract tests following this repo's route-test convention.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /session/start | Untrusted deckIds; a user could try to associate a session with decks they cannot access |
| client → POST /session/complete | Untrusted sessionId + cardsReviewed; a user could try to complete another user's session or inflate duration |
| client → POST /rate | Untrusted thinkingTimeMs (display stat) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30-01 | Tampering (IDOR) | POST /session/complete | high | mitigate | Load session and reject with 403 unless `session.userId === c.get('userId')` before any update — never update by id alone |
| T-30-02 | Tampering | POST /session/start deckIds | medium | mitigate | Validate every deckId against deck ownership OR active DeckShare (reuse /rate guard) before creating StudySessionDeck rows; 403 if any fails |
| T-30-03 | Spoofing | client-supplied durationSeconds | medium | mitigate | Server computes durationSeconds from persisted startedAt→now; the complete schema has no duration field, so a tampered client value is structurally impossible |
| T-30-07 | Tampering | client-supplied thinkingTimeMs / cardsReviewed | low | accept | Inherently client-measured display stats; Zod bounds to nonnegative int; no security decision derives from them |
| T-30-SC | Tampering | npm/pip/cargo installs | low | accept | No new package installs — routes use existing prisma + shared schemas |
</threat_model>
