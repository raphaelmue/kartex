<objective>
Fix the CRITICAL UAT Gap 1: the public invite-validation route `GET /api/invites/:token` is being intercepted by `authMiddleware` and returns 401, causing the frontend to show "Your session has expired" and redirect unauthenticated invitees to `/login` instead of rendering the invite registration/error page.

The public router (`invitesPublicRouter`) is registered before `app.use('/api/*', authMiddleware)` in `index.ts`, but in the deployed Hono v4 build the catch-all auth middleware still runs first for `/api/invites/*` (confirmed in incognito — UAT test 8). The robust, order-independent fix is to make `authMiddleware` itself bypass the public invite prefix.

Purpose: Closes EMAIL-06 — invitees (who have no session) must be able to load `/invite/<token>` and see the registration form or the "already used / invalid / expired" error card. This also unblocks UAT tests 4–7, which were blocked only because no invitee could reach a public invite page.
Output: A scoped path-prefix bypass inside `authMiddleware` plus a focused middleware test proving public reachability without weakening any protected route.
</objective>
