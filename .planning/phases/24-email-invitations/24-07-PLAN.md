<objective>
Fix UAT Gap 2 and Gap 3.

Gap 2 (major): When SMTP is configured but delivery fails, `admin.ts` POST /invites rolls back the token (correct) and returns the raw nodemailer error message in a 500. The frontend `handleSendInvite` only maps the literal `'SMTP not configured.'` string, so a real delivery failure shows the generic fallback at best and leaked internal error text at worst — the admin gets no actionable signal and the pending table stays empty with no explanation (UAT tests 2 and 3). Fix: return a stable opaque code `SMTP_ERROR` from the backend (logging the real cause server-side), and map `SMTP_ERROR` (plus any other unexpected 500) to a clear, localized toast on the frontend.

Gap 3 (cleanup): `packages/shared/src/schemas/inviteCode.ts` is dead (Phase 23 replaced the InviteCode table with InviteToken) but is still exported from `packages/shared/src/index.ts`, and `apps/backend/src/routes/__tests__/admin-delete.test.ts` still has a stale assertion block referencing the dropped `InviteCode` FK. Remove the dead schema/export and correct the stale test.

Purpose: Completes EMAIL-03/EMAIL-04 (send invitation) by giving the admin reliable, non-leaky feedback when delivery fails, and clears Phase-23 dead code so the InviteToken model is the single source of truth.
Output: Coded backend error, localized frontend mapping with a new i18n key + test, and removal of the dead invite-code schema and stale test.
</objective>
