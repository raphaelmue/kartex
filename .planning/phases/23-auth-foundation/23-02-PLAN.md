<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → POST /mailer/test | Authenticated admin triggers an outbound email; protected by requireAdmin middleware |
| backend → SMTP server | Credentials cross to the SMTP provider; must never be logged or returned in responses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-02 | Information disclosure | SMTP credentials | mitigate | Credentials read from env vars only; never logged (only `[mailer] SMTP configured.` boolean logged) and never returned in API responses |
| T-23-03 | Spoofing / abuse | POST /mailer/test | mitigate | Test email is hard-targeted at the logged-in admin's own email (c.get('userId') lookup) — admin cannot send to arbitrary addresses; route behind requireAdmin |
| T-23-DoS | Denial of service | verify() at startup | mitigate | verifyConnection() is called only in the test endpoint, never at module init, so a down SMTP server cannot block server startup (D-10 soft-fail) |
| T-23-SC | Tampering | nodemailer install | mitigate | Package legitimacy verified in blocking Task 0 checkpoint before install (nodemailer 18M wk downloads, 13yr old; SUS flag was version-recency only) |
</threat_model>
