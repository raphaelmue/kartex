## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `px-1`) | Icon gaps, hairline separators |
| sm | 8px (`px-2`, `gap-2`) | Nav icon-to-label gap, footer inner gaps |
| md | 16px (`px-4`) | Topbar horizontal padding, footer horizontal padding, sidebar horizontal padding |
| lg | 24px (`p-6`) | Not used in shell — reserved for page content |
| xl | 32px (`p-8`) | Main content area padding (existing `p-8` on `<main>`) |
| 2xl | 48px | Not used in shell |
| 3xl | 64px | Not used in shell |

Exceptions:
- Touch target minimum: 44px height for hamburger button — use `h-11` (44px) matching existing nav link height. Source: existing `h-11` on navItems.
- Topbar height: 64px (`h-16`) — matches existing sidebar brand area height `h-16` for visual consistency.
- Sidebar width: 240px (`w-60`) — existing value, unchanged.
- Footer height: 40px (`h-10`) — fixed-height sibling row below `<main>`.
- Drawer width: 240px (`w-60`) — mirrors sidebar width for visual continuity.

## Color

All values reference the CSS custom properties declared in `src/index.css`. Light and dark mode values included.

| Role | CSS Token | Light Value | Dark Value | Usage |
|------|-----------|-------------|------------|-------|
| Dominant (60%) | `--background` | `hsl(0 0% 98%)` near-white | `hsl(0 0% 4%)` near-black | Main content area `bg-background` |
| Secondary (30%) | `--card` | `hsl(0 0% 100%)` white | `hsl(0 0% 9%)` dark card | Sidebar `bg-card`, topbar `bg-card`, drawer panel `bg-card` |
| Accent (10%) | `--accent` | `hsl(0 0% 96%)` light gray | `hsl(0 0% 15%)` dark gray | Active nav item highlight only |
| Border | `--border` | `hsl(0 0% 90%)` | `hsl(0 0% 15%)` | Sidebar border-r, footer border-t |
| Muted text | `--muted-foreground` | `hsl(0 0% 45%)` | `hsl(0 0% 64%)` | Footer text, username display |
| Destructive | `--destructive` | `hsl(0 84% 60%)` | `hsl(0 62% 30%)` | Not used in this phase |

Accent reserved for: active nav link background (`bg-accent`) and active nav icon/label color (`text-accent-foreground`). No other elements use accent in this phase.

**Backdrop (overlay):**
- Color: `bg-black/50` — 50% opacity black overlay.
- Renders over `bg-background` content area only (right of sidebar column) when drawer is open.
- `position: fixed` covering the right portion, or `inset-0` with `z-40` behind drawer panel.

**Topbar background:**
- `bg-card` with `border-b border-border` — matches the sidebar card surface. Visually unified with the sidebar on mobile.

## Dimension 1 — Layout & Spacing

### Breakpoints

| Breakpoint | Tailwind prefix | Value | Behavior |
|------------|-----------------|-------|----------|
| Mobile | (none / default) | < 768px | Topbar visible, sidebar hidden, drawer available |
| Desktop | `md:` | ≥ 768px | Topbar hidden, sidebar always visible, no drawer |

### Structural Layout

**Current AppShell (desktop, unchanged):**
```
<div class="flex h-screen overflow-hidden">
  <aside class="w-60 bg-card border-r ...">  ← fixed sidebar
  <div class="flex flex-col flex-1 min-h-0"> ← RIGHT COLUMN (new wrapper)
    <header class="h-16 flex md:hidden ..."> ← mobile topbar (new)
    <main class="flex-1 overflow-y-auto bg-background p-8">
    <footer class="h-10 shrink-0 border-t ..."> ← footer (new)
  </div>
</div>
```

**Key layout rules:**
- Sidebar: `hidden md:flex` (hidden on mobile, flex column on desktop).
- Right column wrapper: `flex flex-col flex-1 min-h-0` — `min-h-0` required to prevent flex child overflow on Safari.
- Mobile topbar: `flex items-center md:hidden h-16 px-4 bg-card border-b border-border` — `md:hidden` hides on desktop.
- Main: `flex-1 overflow-y-auto bg-background p-8` — `flex-1` grows to fill remaining space between topbar and footer.
- Footer: `h-10 shrink-0 border-t border-border flex items-center justify-between px-4 text-xs text-muted-foreground`.

### Drawer (mobile overlay)

- Drawer panel: `position: fixed`, `top-0 left-0 h-full w-60 bg-card border-r border-border z-50 flex flex-col`.
- Backdrop: `position: fixed`, `inset-0 bg-black/50 z-40` — z-index 40 behind drawer (z-50).
- Drawer is NOT rendered in DOM when closed (conditional render, not visibility:hidden) — avoids focus trapping issues.
- Drawer panel mirrors the desktop aside markup exactly (same navItems, user area, theme toggle, logout).

### Z-index stacking

| Layer | z-index | Tailwind |
|-------|---------|---------|
| Page content | 0 | (base) |
| Backdrop | 40 | `z-40` |
| Drawer panel | 50 | `z-50` |

## Dimension 4 — Component Contracts

### Hamburger button
```
<Button
  variant="ghost"
  size="icon"
  aria-label="Open navigation menu"
  onClick={() => setDrawerOpen(true)}
>
  <Menu className="h-5 w-5" aria-hidden="true" />
</Button>
```
- Uses existing shadcn `Button` with `variant="ghost" size="icon"` — identical pattern to the theme toggle button already in `AppShell`.
- The `Menu` icon from `lucide-react` must be added to the import list in `AppShell.tsx`.

### Mobile drawer panel
- Renders the same nav markup as the desktop `<aside>`: `navItems` map, conditional Admin link, user area with theme toggle and logout button.
- Each `NavLink` in the drawer receives `onClick={() => setDrawerOpen(false)}` to close the drawer on navigation.
- No X / close button inside the drawer (D-06 is explicit).

### Backdrop element
```
<div
  className="fixed inset-0 bg-black/50 z-40"
  aria-hidden="true"
  onClick={() => setDrawerOpen(false)}
/>
```
- Rendered only when `drawerOpen === true`.
- `aria-hidden="true"` — purely presentational; screen readers navigate through the drawer panel itself.

### Footer component
- Can be an inline `<footer>` element inside the right-column wrapper in `AppShell.tsx`, or extracted to `AppFooter.tsx`. Executor discretion.
- Version string: imported via `import packageJson from '../../package.json'` with `assert { type: 'json' }` or via `import.meta.env.VITE_APP_VERSION` populated by Vite config. Executor discretion on exact mechanism.
- Footer links are `<a href="..." target="_blank" rel="noopener noreferrer">`.
- Footer link constants defined at top of the footer file/component:
  ```ts
  const GITHUB_URL = 'https://github.com/raphael-mueller/kartex'
  const DOCS_URL = 'https://github.com/raphael-mueller/kartex#readme'
  ```
  Note: Planner should verify canonical GitHub URL from git remote config before hardcoding.

### NavLink (existing, drawer context)
- In the drawer, `NavLink` className function is identical to the sidebar version.
- Drawer `onClick` handler placed on the `NavLink` wrapper: `onClick={() => setDrawerOpen(false)}`.

## Dimension 5 — Interaction & Motion

### Drawer open/close animation
- Slide-in from left: `transform translate-x-0` (open) ↔ `transform -translate-x-full` (closed).
- Transition: `transition-transform duration-200 ease-in-out` — 200ms is fast enough to feel responsive without lag.
- Implementation pattern:

```tsx
<div
  className={cn(
    'fixed top-0 left-0 h-full w-60 bg-card border-r border-border z-50 flex flex-col',
    'transition-transform duration-200 ease-in-out',
    drawerOpen ? 'translate-x-0' : '-translate-x-full'
  )}
>
```

Note: Conditional render vs CSS transform toggle are both valid. Using CSS transform (always in DOM, toggled via class) provides smoother animation. Executor discretion if they prefer conditional render instead — the contract only requires 200ms ease-in-out.

### Backdrop fade-in/out
- `transition-opacity duration-200` with `opacity-100` (open) / `opacity-0` (closed).
- Or use conditional render (simpler, no flash). Executor discretion.
- If using conditional render for both: no transition classes needed — the 200ms slide handles perceived smoothness.

### Hamburger → X icon transition
- No hamburger-to-X swap required (D-06: drawer closes via backdrop/nav link, not a button).
- The hamburger button remains a static "open" trigger only. It is hidden when the drawer is open because the topbar is behind the backdrop (`z-40`) and the hamburger is part of the topbar (z below backdrop).

### State
- `drawerOpen: boolean` — `useState(false)` local to `AppShell` (or `MobileSidebar` if extracted).
- No need for context — drawer state is local to shell layout.
- Drawer always starts closed (`false`). No persistence across page loads.

## Dimension 6 — Accessibility

### Hamburger button
- `aria-label="Open navigation menu"` — explicit, describes the action.
- `aria-expanded` attribute: `aria-expanded={drawerOpen}` — communicates drawer state to screen readers.
- `aria-controls="mobile-nav-drawer"` — reference to drawer panel `id`.

### Drawer panel
- `id="mobile-nav-drawer"` — referenced by hamburger's `aria-controls`.
- `role` is implicit (`div` with nav inside — the inner `<nav aria-label="Main navigation">` carries semantic weight).
- Focus management: when the drawer opens, move focus to the first nav link inside the drawer (`useEffect` + `ref.focus()`). When the drawer closes (via backdrop click), return focus to the hamburger button.
- Executor discretion on whether to implement a full focus trap (recommended for production accessibility but not strictly required for this phase). At minimum: focus moves into the drawer on open.

### Backdrop
- `aria-hidden="true"` — screen readers should not encounter the backdrop.
- `tabIndex={-1}` — not keyboard-focusable.

### Footer landmark
- Use semantic `<footer>` element — browser UA stylesheet applies `role="contentinfo"` automatically.
- No `aria-label` needed when there is only one footer on the page.
- Footer links: standard `<a>` with visible text labels (`GitHub`, `Docs`) — no icon-only links.

### Mobile topbar
- Use semantic `<header>` element for the topbar.
- Page title `<span>` does not need a role — it is purely presentational text. Screen readers will read the `<title>` element (set per-page) for page context.

### Navigation (existing, unchanged)
- `<nav aria-label="Main navigation">` is already present in the sidebar. The drawer uses the same markup, so both navigation regions carry the same label. This is acceptable because only one is visible/focusable at a time (sidebar hidden on mobile, drawer hidden on desktop).
