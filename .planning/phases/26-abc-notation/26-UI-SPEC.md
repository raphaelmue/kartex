| Role | Size | Weight | Line Height | Context |

## Color

All color values are CSS-variable tokens from `apps/frontend/src/index.css`.
No hardcoded hex values are used in this phase.

| Role | Token | Light value | Dark value | Usage in AbcBlock |
|------|-------|-------------|------------|-------------------|
| Dominant (60%) | `hsl(var(--background))` | `hsl(0 0% 98%)` | `hsl(0 0% 4%)` | Page/card background surrounding AbcBlock |
| Secondary (30%) | `hsl(var(--card))` | `hsl(0 0% 100%)` | `hsl(0 0% 9%)` | Card surface that contains KartexRenderer |
| Muted text | `hsl(var(--muted-foreground))` | `hsl(0 0% 45%)` | `hsl(0 0% 64%)` | Loading label and raw-source text in error block |
| Destructive | `hsl(var(--destructive))` | `hsl(0 84% 60%)` | `hsl(0 62% 30%)` | Error block border, error heading text |
| Destructive surface | `hsl(var(--destructive) / 5%)` | near-white tint | near-transparent | `bg-destructive/5` in RenderErrorBlock |

Accent (`hsl(var(--accent))`) is not used in this phase.

**Dark-mode SVG inversion (D-03):** The AbcBlock success-state container div
uses the Tailwind utility `dark:invert`. This is a CSS filter (`filter: invert(1)`)
applied on the `.dark` body class — no color token, no component prop.
abcjs renders black notes on white SVG; `dark:invert` flips this to white
notes on black, which blends correctly with `--background: 0 0% 4%` in dark mode.

## Component Render States

This is the primary contract section for this phase. AbcBlock has exactly
three exclusive render states.

### State 1 — Loading

**Trigger:** Component is mounted and `import('abcjs')` has not yet resolved.

**DOM structure:**

```
<span class="text-muted-foreground text-sm">
  <Loader2 class="h-4 w-4 animate-spin inline mr-1" />
  Rendering...
</span>
```

**Constraints:**
- Loader2 icon: 16px × 16px (`h-4 w-4`), `animate-spin` CSS animation.
- Display: `inline` (not block) — consistent with TypstBlock.
- Label text: "Rendering..." — same literal string as TypstBlock loading state.
- No skeleton placeholder, no height reservation. Component collapses to
  inline height until SVG renders. This matches the existing TypstBlock
  pattern and is intentional.
- Source: pre-populated from D-04 + existing TypstBlock pattern (lines 68–75
  of `KartexRenderer.tsx`).

### State 2 — Error

**Trigger:** `renderAbc()` returns an object whose `warnings` array is
non-empty AND no SVG element was written to the container div.

**DOM structure:** Reuse the existing `RenderErrorBlock` component verbatim:

```
<div class="border border-destructive rounded p-2 my-1 bg-destructive/5">
  <p class="text-destructive text-xs font-medium">ABC render error: {message}</p>
  <pre class="text-xs mt-1 font-mono text-muted-foreground">{rawSource}</pre>
</div>
```

**Props:**
- `heading`: `"ABC render error"` (literal string, not i18n key — see Copywriting).
- `errorMessage`: First item from `warnings` array returned by `renderAbc()`,
  or `"Unknown error"` if the array is empty but the condition is still met.
- `rawSource`: The raw ABC notation string passed to `AbcBlock` as `source`.

**Constraints:**
- `RenderErrorBlock` is imported/used unchanged — no new variant.
- Error block uses `rounded` (4px, `--radius` minus 4px override) per existing
  class — matches the rest of the design system.
- Source: pre-populated from D-05 + lines 22–29 of `KartexRenderer.tsx`.

### State 3 — Success

**Trigger:** `import('abcjs')` resolves and `renderAbc()` returns with empty
or absent `warnings`.

**DOM structure:**

```
<div class="w-full dark:invert" ref={containerRef} />
```

abcjs mutates `ref.current` directly, writing an SVG child into this div.

**Constraints:**
- Container: `div` element with `ref` — NOT `dangerouslySetInnerHTML`.
  (Key difference from TypstBlock which uses SVG string injection. AbcBlock
  uses the abcjs DOM-mutation API per v1.4-research STATE.md decision.)
- `w-full`: Makes the container 100% of its parent's width. Required for
  `responsive: 'resize'` to function — abcjs reads the container width to
  compute SVG `viewBox`. Source: D-02.
- `dark:invert`: CSS filter only, no JS. Applied unconditionally — not
  toggled on theme change. CSS handles the toggle via `.dark` ancestor class.
  Source: D-03.
- No `overflow-hidden`, no `max-h`, no `aspect-ratio`. SVG height is
  determined by abcjs from the notation content.
- abcjs `renderAbc()` options (minimum required): `{ responsive: 'resize' }`.
  Additional options (`add_classes`, `format`) are at implementer's discretion
  (Claude's Discretion from CONTEXT.md §Decisions).

## Copywriting Contract

This phase introduces no page-level CTAs, no empty states, and no destructive
actions. The only user-visible strings are renderer-internal labels within
`AbcBlock`.

| Element | Copy | Localized? |
|---------|------|------------|
| Loading label | `"Rendering..."` | No — matches TypstBlock (established pattern; renderer messages are not i18n keys per STATE.md decision 02-02 and TypstBlock source) |
| Error heading | `"ABC render error"` | No — same convention as `"Typst render error"` in TypstBlock (line 80 of KartexRenderer.tsx) |
| Error message body | Sourced from `abcjs` `warnings[0]` — not authored | No |
| Destructive confirmation | None — no destructive actions in this phase | — |
| Empty state | None — no data-bearing page views in this phase | — |
| Primary CTA | None — renderer component, no user-initiated action | — |

**Rationale for no i18n:** The `RenderErrorBlock` heading and the loading
label follow the existing TypstBlock pattern where these strings are hardcoded
English literals. This was established in the project design decisions and
confirmed in CONTEXT.md. No new i18n keys are required for Phase 26.

## Dependency Contract

`abcjs` is the only new dependency introduced in this phase.

| Package | Version | Install target | Registry type |
|---------|---------|---------------|---------------|
| `abcjs` | `^6.6.3` | `apps/frontend` | npm (not shadcn) |

Install command: `yarn workspace @kartex/frontend add abcjs`

**abcjs CSS import:** abcjs ships optional CSS for playback UI elements.
Since audio playback is explicitly deferred to v2 (CONTEXT.md §Deferred),
no abcjs CSS import is required. The SVG-only render path requires no
external stylesheet. Confirm during implementation that `renderAbc()` with
`responsive: 'resize'` produces correct output without a CSS import; if a
stylesheet is required for core SVG rendering, import it in `main.tsx`
alongside the existing KaTeX and highlight.js CSS imports.
