<action>
In `apps/backend/prisma/schema.prisma`, make two edits:

Edit 1 — Add relation to User model: in the User model body, after the line `refreshTokens  RefreshToken[]`, add `resetTokens    PasswordResetToken[]`.

Edit 2 — Add new model after the InviteToken model block:

Model name: `PasswordResetToken`
Fields:
- `id` — String, @id @default(cuid())
- `userId` — String
- `user` — User relation: fields [userId], references [id], onDelete: Cascade (this ensures auto-deletion when the user is deleted — no manual cleanup needed in the admin delete transaction, per D-07 security pattern and v1.4-research decision)
- `tokenHash` — String @unique (stores SHA-256 hash only; the raw token is never persisted — D-07)
- `expiresAt` — DateTime (1-hour window enforced at query time per RESET-02)
- `usedAt` — DateTime? (nullable; null = unused, non-null = consumed — single-use gate)
- `createdAt` — DateTime @default(now())

Do NOT add an `email` field to PasswordResetToken. The user's email is retrieved at runtime via the User relation.

Contrast with InviteToken: InviteToken has no userId FK (created before user exists). PasswordResetToken is always user-bound, so a FK with onDelete: Cascade is correct.
</action>

Inside it, create `migration.sql`.

The file content must follow the conventions established in prior hand-written migrations:
- Opening comment block: one-line description stating this creates the PasswordResetToken table (implements RESET-02), stores only the SHA-256 hash of the raw token, uses ON DELETE CASCADE so tokens auto-delete with the user, and is applied via `prisma migrate deploy` in the Docker Compose entrypoint
- CREATE TABLE "PasswordResetToken" with columns: "id" TEXT NOT NULL, "userId" TEXT NOT NULL, "tokenHash" TEXT NOT NULL, "expiresAt" TIMESTAMP(3) NOT NULL, "usedAt" TIMESTAMP(3) (nullable — no NOT NULL), "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP, and CONSTRAINT "PasswordResetToken_pkey" PRIMARY KEY ("id")
- CREATE UNIQUE INDEX "PasswordResetToken_tokenHash_key" ON "PasswordResetToken"("tokenHash")

This migration is additive only — no DROP TABLE or DROP COLUMN statements.

The migration is NOT applied by `prisma migrate dev` (unavailable in driver adapter mode without DATABASE_URL in the shell environment — per 10-02 and 24-01 decisions). It is applied at container startup via `prisma migrate deploy` in the Docker Compose entrypoint.
</action>
