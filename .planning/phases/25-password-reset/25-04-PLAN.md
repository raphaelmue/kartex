### Task 4.2: Create ResetPasswordPage.tsx

<read_first>
- apps/frontend/src/pages/InviteRegisterPage.tsx — full file: exact status state machine pattern (lines 37–43), token from useParams (line 33), mount fetch effect (lines 56–80), error render (lines 129–155), form render (lines 157–267); confirm-password ref pattern (lines 41–42, 230–236)
- packages/shared/src/schemas/auth.ts — PasswordResetSchema and PasswordResetInput (from Plan 25-01)
</read_first>

<action>
Create `apps/frontend/src/pages/ResetPasswordPage.tsx` as a named export `ResetPasswordPage`. Model it closely on InviteRegisterPage.tsx — the structure is near-identical with adapted fields and i18n keys.

State:
- `status`: useState with type `'loading' | 'ok' | 'error'`, initial `'loading'`
- `errorCode`: useState<string | null>, initial null
- `confirmPassword`: useState('') — controlled input value for the confirm-password field
- `confirmPasswordRef`: useRef('') — stable closure value compared on submit
- `confirmError`: useState<string | null>, initial null

Token: `const { token } = useParams<{ token: string }>()` (same as InviteRegisterPage line 33).

Document title: useEffect setting `document.title` to `t('auth.resetPageTitle')` with `[t, i18n.language]` dependencies.

Mount validation effect (mirrors InviteRegisterPage lines 56–80):
- If token is falsy: setErrorCode('NOT_FOUND'), setStatus('error'), return
- Call `api.get('/api/auth/reset-password/' + token)` then:
  - If res.ok: setStatus('ok') — no data extraction needed (unlike InviteRegisterPage which extracts email)
  - If not ok: parse body JSON, setErrorCode((body as { error?: string }).error ?? 'NOT_FOUND'), setStatus('error')
  - On catch: setErrorCode('NOT_FOUND'), setStatus('error')
- Dependency array: [token]

Form: useForm with PasswordResetSchema and zodResolver, defaultValues `{ newPassword: '' }`, typed as PasswordResetInput.

onSubmit handler:
1. Compare `values.newPassword` against `confirmPasswordRef.current`; if mismatch: setConfirmError(t('auth.passwordMismatch')), return.
2. setConfirmError(null).
3. Call `api.post('/api/auth/reset-password/' + token, { newPassword: values.newPassword })`.
4. If res.ok: `navigate('/login', { state: { passwordReset: true } })` (D-01 — triggers success toast on LoginPage).
5. If not ok: parse body error code and call toast.error with the matching i18n key: ALREADY_USED → t('auth.resetLinkUsed'), EXPIRED → t('auth.resetLinkExpired'), default → t('common.somethingWrong').
6. On catch: toast.error(t('common.somethingWrong')).

Render order (mirrors InviteRegisterPage conditional structure):
1. Loading: centered Card with CardContent containing Loader2 animate-spin with aria-label t('common.loading') (same as InviteRegisterPage lines 114–127)
2. Error: centered Card with CardHeader (CardTitle `t('auth.resetErrorTitle')`), CardContent (p with error message derived from errorCode mapping: ALREADY_USED → t('auth.resetLinkUsed'), EXPIRED → t('auth.resetLinkExpired'), default → t('auth.resetLinkInvalid')), CardFooter (Link to "/login" with t('auth.backToSignIn'))
3. Form: centered Card with CardHeader (CardTitle `t('auth.resetPasswordTitle')`, CardDescription `t('auth.resetPasswordDesc')`), two password fields (newPassword as FormField + confirmPassword as manual controlled Input below it, same as InviteRegisterPage lines 220–242), submit button showing t('auth.resettingPassword') when isSubmitting

The confirmPassword Input: use useId() for its htmlFor/id pairing (same as InviteRegisterPage `confirmId`). The onChange handler updates both `confirmPassword` state and `confirmPasswordRef.current`, and clears `confirmError`. Render `confirmError` paragraph below the Input using text-destructive class.

Imports needed: zodResolver, useForm, useTranslation, Link, useNavigate, useParams, useState, useEffect, useId, useRef, toast from sonner, Loader2, PasswordResetSchema + PasswordResetInput from @kartex/shared, api, Button + Card family + Form family + Input.

File must stay under 500 lines.
</action>
