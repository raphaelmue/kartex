<objective>
Extend the deck-update backend (Phase 16) to accept `.kartex.zip` bundles containing media. The work is extraction + wiring: lift the zip media logic that already exists in `import.ts` into a shared `importMedia.ts` helper, refactor `import.ts` to consume it (no behavior change), then add a zip branch to both the preview and apply handlers in `deckUpdate.ts`.

Purpose: Deck owners can update a deck in place from a bundle that includes images/audio, with media validated by magic bytes, stored under server-generated UUIDs, and card content rewritten to reference those UUIDs — while SM-2 progress for kartexId-matched cards stays untouched.

Output: `importMedia.ts` shared helper + tests, refactored `import.ts`, extended `deckUpdate.ts` + extended `deck-update.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> deck-update API | Untrusted multipart file (zip) and form fields cross here; client-declared MIME and filenames are not trusted |
| zip entry -> filesystem | Zip entry paths/names are attacker-controlled; only server-generated UUID names may reach disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-01 | Tampering | deckUpdate.ts zip media entry path | high | mitigate | Storage filename is `randomUUID() + '.' + detected.ext` via storeMediaBuffers; `basename()` strips any directory component — raw zip path never reaches `writeFile` |
| T-27-02 | Tampering | deckUpdate.ts media validation | high | mitigate | `collectAndValidateMedia` uses `fileTypeFromBuffer` magic bytes against ALLOWED_MIMES; client `file.type` and extensions are ignored |
| T-27-03 | Denial of Service | zip upload size | high | mitigate | `bodyLimit(MAX_BYTES)` first in chain (pre-parse 413); `MAX_MEDIA_ENTRIES=100`; `MAX_TOTAL_BYTES = MAX_BYTES * 10` uncompressed ceiling; per-entry size check |
| T-27-04 | Elevation of Privilege | deckUpdate.ts owner gate | high | mitigate | `deck.ownerId !== userId -> 403` runs before any zip processing in both handlers; re-checked statelessly on apply (TOCTOU) |
| T-27-05 | Tampering | media UUID provenance | medium | mitigate | Stored UUIDs come only from server `randomUUID()`; rewriteMediaRefs maps original->UUID; client cannot inject a stored filename |
| T-27-06 | Spoofing | macOS `__MACOSX/` metadata entries | low | mitigate | Media filter skips `__MACOSX/` and directory entries (replicated from import.ts) |
| T-27-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages — unzipper/file-type/hono already in production; RESEARCH Package Legitimacy Audit shows all existing deps, no install task |
</threat_model>
