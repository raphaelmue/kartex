## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding |
| sm | 8px | Chip label-to-value gap, row cell padding |
| md | 16px | Chip internal padding (`p-4`), section horizontal padding (`px-4`) |
| lg | 24px | Between chip row and per-deck section (`mb-6`) |
| xl | 32px | Between hero section and stats panel (`mb-8`) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Stat chip touch target minimum: 44px height (accessibility — tall enough for mobile tap). Achieve via `min-h-[44px]` on each chip div.
- Per-deck table rows inherit shadcn Table default row height (~40px).

Source: Matches existing DashboardPage.tsx chip pattern (`p-4`, `mb-8`, `px-4 py-8`).

## Typography

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Display (due count hero) | 48px (text-5xl) | 600 (font-semibold) | 1.2 | `text-5xl font-semibold` |
| Heading (section label) | 20px (text-xl) | 600 (font-semibold) | 1.2 | `text-xl font-semibold` |
| Body | 16px (text-base / text-sm = 14px) | 400 (font-normal) | 1.5 | `text-sm font-normal` |
| Chip label | 12px (text-xs) | 400 (font-normal) | 1.4 | `text-xs font-normal uppercase tracking-wide` |

Rules:
- Stat chip primary value: `text-xl font-semibold text-foreground` — matches existing "Reviewed today" and "Streak" chips exactly (D-08 / decision 04-03).
- Stat chip label: `text-xs font-normal text-muted-foreground uppercase tracking-wide` — matches existing pattern.
- Empty state copy inside a chip: `text-sm font-normal text-muted-foreground` — no numeric display, just the message.
- Per-deck section heading: none — the section is introduced by a table header row, matching the existing `byDeck` table pattern.
- Per-deck deck name: `text-sm font-normal text-foreground` — matches existing `byDeck` link style.

Source: Extracted verbatim from `apps/frontend/src/pages/DashboardPage.tsx` lines 63–155.

## Color

All colors use shadcn CSS variable tokens. No raw hex values are allowed in component code.

| Role | CSS Token | Light Value | Dark Value | Usage |
|------|-----------|-------------|------------|-------|
| Dominant (60%) | `bg-background` | hsl(0 0% 98%) — near-white | hsl(0 0% 4%) — near-black | Page background, chip backgrounds |
| Secondary (30%) | `bg-muted` / `border-border` | hsl(0 0% 96%) / hsl(0 0% 90%) | hsl(0 0% 15%) | Chip borders, table header |
| Accent (10%) | `text-primary` / `bg-primary` | hsl(0 0% 9%) | hsl(0 0% 98%) | Primary CTA button only |
| Destructive | `text-destructive` | hsl(0 84% 60%) | hsl(0 62% 30%) | Not used in this phase |

Accent reserved for:
- The "Start Studying" Button (already exists) — `bg-primary text-primary-foreground`
- No new accent usage introduced in Phase 15. Stats chips use `border-border` and `text-foreground`/`text-muted-foreground` only.

Semantic colors for stat elements:
- Difficulty breakdown: Easy/Good/Hard/Again counts are plain `text-foreground` numbers — no traffic-light colors. Avoids color-only information encoding (accessibility).
- Retention rate value: `text-foreground font-semibold` — no green/red threshold coloring.
- Mastered count: `text-foreground` — no special color.
- Due count in per-deck table: `Badge variant="secondary"` when > 0 (matches existing byDeck pattern, decision 04-03).

Source: `apps/frontend/src/index.css` CSS variable declarations.

## Layout Contract

### DashboardPage section order (top → bottom)

1. **Hero section** — due count + "Start Studying" / all-caught-up state (existing, unchanged)
2. **Per-deck due table** — existing `byDeck` table (existing, unchanged)
3. **Existing stat chips row** — "Reviewed today" + "Streak" (existing, unchanged)
4. **NEW: StatsSummaryPanel** — inserted below existing chips, same `max-w-2xl mx-auto px-4` container

### StatsSummaryPanel internal layout

```
┌──────────────────────────────────────────┐
│ Row 1: [Total Reviewed chip] [Retention chip]  ← flex gap-4
├──────────────────────────────────────────┤
│ Row 2: [Difficulty Breakdown chip — full width] ← mt-4
├──────────────────────────────────────────┤
│ Row 3: Per-Deck Progress table           ← mt-6
│  Deck | Due | Mastered | In Learning     │
└──────────────────────────────────────────┘
```

**Total Reviewed chip** (STATS-01):
- Label: `t('dashboard.stats.totalReviewed')` → "Total Reviewed"
- Primary value: all-time count (integer, e.g. "1,234")
- Secondary line: `text-xs text-muted-foreground` → `t('dashboard.stats.thisWeek', { count })` → "{{count}} this week"

**Retention Rate chip** (STATS-02):
- Label: `t('dashboard.stats.retentionRate')` → "Retention Rate (30 days)"
- Value when data: `"{{n}}%"` formatted integer (e.g. "87%"), `text-xl font-semibold`
- Value when empty: `t('dashboard.stats.noData')` → "No data yet", `text-sm text-muted-foreground`

**Difficulty Breakdown chip** (STATS-03):
- Label: `t('dashboard.stats.difficultyBreakdown')` → "Difficulty Breakdown"
- Value when data: four inline items — Easy · Good · Hard · Again — each `<span className="text-sm font-semibold">N</span> <span className="text-xs text-muted-foreground">Easy</span>` separated by thin vertical dividers (`border-l border-border mx-2`)
- Value when empty: `t('dashboard.stats.noData')` → "No data yet", `text-sm text-muted-foreground`
- Full width: `className="border border-border rounded-lg p-4 mt-4 min-h-[44px]"` (no flex-1)

**Per-Deck Progress table** (STATS-04):
- Section label above table: `<p className="text-sm font-semibold text-foreground mb-2">{t('dashboard.stats.perDeckProgress')}</p>`
- Table columns: Deck | Due | Mastered | In Learning
- Column headers: `text-xs font-normal uppercase tracking-wide text-muted-foreground`
- Deck cell: deck name as plain text (non-clickable — deck link already in existing byDeck table above)
- Due cell: `Badge variant="secondary"` when > 0, plain muted number when 0
- Mastered cell: plain `text-sm text-foreground` number
- In Learning cell: plain `text-sm text-foreground` number
- Empty table state (no decks): single row "No decks yet." centered, `text-sm text-muted-foreground`
- Decks with 0 cards: show row with all-zero counts (do NOT hide row)

## Interaction Contract

### Loading behavior

- Stats fetch is fired in parallel with the existing `/api/dashboard/stats` fetch (which drives the hero + byDeck table).
- DashboardPage initiates both fetches simultaneously inside the same `useEffect`. The hero section renders as soon as the first fetch resolves; `StatsSummaryPanel` renders as soon as the second fetch resolves.
- While the stats fetch is pending: `StatsSummaryPanel` renders with all chips in skeleton state — use `bg-muted animate-pulse rounded` placeholder divs (height: 44px each, width: 100%). No shimmer library; pure Tailwind animation.
- After stats fetch resolves: chips render with live data or empty-state copy as appropriate.
- After stats fetch fails (network error or 5xx): `StatsSummaryPanel` renders with all chips in empty state (`"No data yet"` for retention and difficulty; `"0"` for total reviewed; empty per-deck table). No toast. No error message.

### Skeleton pattern

```tsx
// Skeleton placeholder during stats fetch
<div className="flex gap-4 mt-8">
  <div className="flex-1 h-[68px] bg-muted animate-pulse rounded-lg" />
  <div className="flex-1 h-[68px] bg-muted animate-pulse rounded-lg" />
</div>
<div className="h-[68px] bg-muted animate-pulse rounded-lg mt-4" />
<div className="h-[120px] bg-muted animate-pulse rounded-lg mt-6" />
```

### Accessibility requirements

- Each stat chip `<div>` receives `role="region"` and `aria-label` matching its chip label (e.g. `aria-label={t('dashboard.stats.totalReviewed')}`).
- Difficulty breakdown: each rating count has an accessible label. Use `<span className="sr-only">{t('dashboard.stats.easyLabel')}: </span>{count}` pattern so screen readers announce "Easy: 42 Good: 31 Hard: 12 Again: 5".
- Per-deck table: existing shadcn `Table` component provides semantic `<table>` HTML — no additional `role` needed.
- Empty state text in chips has `role="status"` so assistive technology announces the state change when data loads.
- All skeleton placeholders: `aria-hidden="true"` and `aria-busy="true"` on their container.
