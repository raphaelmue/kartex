## Spacing Scale

Identical to Phase 4 (no changes). Declared for executor reference:

| Token | Value | Tailwind class | Usage |
|-------|-------|----------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, inline padding |
| sm | 8px | `gap-2`, `p-2` | Compact element spacing, warning list items |
| md | 16px | `gap-4`, `p-4` | Default element spacing, card preview padding |
| lg | 24px | `gap-6`, `p-6` | Section padding, upload zone vertical padding |
| xl | 32px | `gap-8`, `mb-8` | Layout gaps between major page sections |
| 2xl | 48px | `py-12` | Upload zone height (min-h) |
| 3xl | 64px | `py-16` | Full-page centered empty/success states |

**Exceptions:**
- Upload drop zone: `min-h-[200px]` — content-driven, not grid-aligned. Allows comfortable drag target.
- Card preview list items: `min-h-[80px]` on lazy-loading placeholder (IntersectionObserver sentinel height per RESEARCH.md Pattern 3).
- Touch targets (file picker button): `min-h-[44px]` floor per accessibility requirement.

## UI Areas: Full Interaction Contract

### 1. Import Page (`/import`)

**Route:** Replace `<ComingSoon title="Import" />` in `App.tsx` with `<ImportPage />`.

The page has four machine states driven by `useImport` hook: `UPLOAD`, `PARSING`, `PREVIEW`, `SUCCESS`.

---

#### 1a. UPLOAD State — File Selection Zone

**Layout:** Single-column, centered, `max-w-2xl mx-auto py-8`.

```
[ Import Deck ]                          ← text-xl font-semibold (Heading role)
[ Upload a .kartex file or .kartex.zip bundle to import a deck ]
                                         ← text-sm text-muted-foreground mt-1 mb-8

┌─────────────────────────────────────────────────────────────┐
│  (dashed border, border-dashed border-border rounded-lg)    │
│                                                             │
│  [ Upload icon ]     ← lucide-react Upload, h-10 w-10      │
│                         text-muted-foreground mx-auto mb-4  │
│                                                             │
│  [ Drop your file here, or click to browse ]               │
│    ← text-sm font-normal text-muted-foreground text-center  │
│                                                             │
│  [ .kartex or .kartex.zip · max {N} MB ]                   │
│    ← text-xs text-muted-foreground text-center mt-1        │
│                                                             │
│  [ Browse file ]     ← shadcn Button variant="outline"     │
│                         size="sm", mt-4, mx-auto block     │
└─────────────────────────────────────────────────────────────┘

[ {inline error if file rejected — see §1e} ]
```

**Drop zone behavior:**
- The entire dashed-border area is a valid drag target.
- Drag-over state: `border-primary bg-primary/5` (replaces `border-border bg-background`). Transition: `transition-colors duration-150`.
- Drop: triggers same logic as file picker selection (client-side size check → if passes, transition to PARSING).
- `accept` attribute on the hidden `<input type="file">`: `.kartex,.kartex.zip,application/zip`.
- The "Browse file" Button click programmatically triggers the hidden file input via `ref.current.click()`.
- On small screens (mobile): drop zone behaves as button-only (drag is unavailable on touch; the "Browse file" button fills the interaction). No JS detection needed — just ensure the button is reachable.

**Drop zone sizing:**
- `min-h-[200px]` to provide an adequate drag target.
- `flex flex-col items-center justify-center` internally.
- `p-8` internal padding.

**Client-side file size check (D-11):**
Fires immediately on file selection (before any upload). If `file.size > maxFileSizeBytes` (fetched from `/api/import/config` on page mount): show inline error (§1e). If config fetch failed (graceful degradation): skip check and proceed to PARSING.

---

#### 1b. PARSING State — Upload + Processing Indicator

Shown immediately after file selection passes client-side validation. The upload zone is replaced by a loading block in the same container area.

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  [ Loader2 icon spinning ]  ← lucide-react Loader2,        │
│                                h-8 w-8 animate-spin        │
│                                text-muted-foreground        │
│                                mx-auto mb-3                 │
│                                                             │
│  [ Parsing your file... ]                                   │
│    ← text-sm font-normal text-muted-foreground text-center  │
│                                                             │
│  [ shadcn Progress bar ]    ← determinate if upload %      │
│    ← w-full max-w-xs mx-auto mt-4                          │
│    ← value = upload % (0→100), then indeterminate after    │
└─────────────────────────────────────────────────────────────┘
```

**Progress bar behavior:**
- During multipart upload to `/api/import` (for `.kartex.zip`): determinate, driven by `XMLHttpRequest` `upload.onprogress`. Values 0–100.
- After upload completes (server-side parsing/extraction): switch to `value={undefined}` (shadcn Progress renders as indeterminate/animated pulse). Label text changes to "Extracting and validating...".
- For `.kartex` plain files (client-side parse via `parseKartex()` from `@kartex/shared`): no upload needed. The PARSING state shows for a short time while parse runs (near-instant). No progress bar needed for plain files — show spinner + label only.

**Cancel during upload:** A "Cancel" button appears below the progress: `Button variant="ghost" size="sm"` with label "Cancel". Clicking aborts the XHR (`xhr.abort()`) and returns to UPLOAD state.

#### 1c. PREVIEW State — Parsed Deck Review

Shown after successful parse. Full layout within AppShell `max-w-2xl mx-auto py-8`.

**Layout top-to-bottom:**

```
[ ← Back ]                               ← Button variant="ghost" size="sm", mb-4
                                            Clicking resets to UPLOAD state
                                            Label: "Back", ArrowLeft icon

[ Parse Warnings Banner ]                ← ONLY if warnings.length > 0 (D-06)
  (amber Alert — see §1c-i)

[ Deck Metadata Block ]                  ← Card-like block, mb-6
  (see §1c-ii)

[ Card list label: N cards ]             ← text-sm font-normal text-muted-foreground mb-3
  "Showing {N} cards"

[ Scrollable card preview list ]         ← see §1c-iii
  ...

[ Confirm / Cancel row ]                 ← sticky bottom or fixed below list (see §1c-iv)
```

##### 1c-i. Parse Warnings Banner (D-06 — locked)

Rendered with shadcn `Alert` component, custom amber class overrides. Shown only when `warnings.length > 0`. Hidden entirely when `warnings.length === 0` (no collapsed/toggle state — it is simply absent).

```jsx
<Alert className="border-amber-200 bg-amber-50 text-amber-800 mb-6">
  <AlertTriangle className="h-4 w-4 text-amber-600" />
  <AlertTitle className="text-amber-800 font-semibold text-sm">
    {warnings.length} card{warnings.length > 1 ? 's' : ''} skipped
  </AlertTitle>
  <AlertDescription className="text-amber-800 text-sm mt-1">
    {/* Each warning on its own line */}
    {warnings.map((w, i) => (
      <div key={i}>Card {w.cardIndex}: {w.reason}</div>
    ))}
  </AlertDescription>
</Alert>
```

##### 1c-ii. Deck Metadata Block

Rendered as a `div` with `border border-border rounded-lg p-4 mb-6 bg-card space-y-3`.

```
[ Deck name field ]

  Label: "Deck name"                     ← text-sm font-normal text-foreground mb-1
  shadcn Input                           ← pre-filled with deck.deck from header (D-05)
                                            value controlled by useImport state
                                            onChange updates pendingDeckName

[ Metadata row (if present) ]            ← only rendered when author or tags exist

  Author: {deck.author}                  ← text-sm text-muted-foreground
                                            hidden if deck.author is undefined

  Tags: {deck.tags.join(', ')}           ← flex flex-wrap gap-1, each tag as
                                            shadcn Badge variant="secondary" text-xs
                                            hidden if deck.tags is empty

[ Total cards ]
  {cards.length} cards imported          ← text-sm text-muted-foreground
  ({warnings.length} skipped)            ← only if warnings.length > 0; same line, text-amber-600
```

The deck name `Input` is the only interactive field. No validation of deck name beyond non-empty on submit (if empty, the confirm button is disabled).

##### 1c-iii. Card Preview List (D-04, D-05, IMPT-05 — locked)

Rendered as a `div className="space-y-3"`. Each card is a `LazyCard` component using `IntersectionObserver`.

**LazyCard — placeholder (before scrolled into view):**
```jsx
<div className="border border-border rounded-lg p-4 min-h-[80px] animate-pulse bg-muted/30" />
```

**LazyCard — loaded (once visible):**
```jsx
<div className="border border-border rounded-lg p-4 space-y-2">
  <div className="text-xs font-medium text-muted-foreground uppercase tracking-wide">Front</div>
  <KartexRenderer content={card.front} />
  <hr className="border-border my-2" />
  <div className="text-xs font-medium text-muted-foreground uppercase tracking-wide">Back</div>
  <KartexRenderer content={card.back} />
  {card.tags.length > 0 && (
    <div className="flex flex-wrap gap-1 mt-2">
      {card.tags.map((tag) => (
        <Badge key={tag} variant="secondary" className="text-xs">{tag}</Badge>
      ))}
    </div>
  )}
</div>
```

**Card index label:** No per-card number shown (avoids confusion with warning card indices). The count is shown in the metadata block above the list.

**IntersectionObserver options:** `{ threshold: 0.1, rootMargin: '200px' }`. The 200px root margin pre-renders cards slightly before they enter the viewport, avoiding visible pop-in during normal scroll speed.

**Once visible:** `setVisible(true)` and `observer.disconnect()` — never reverts to placeholder.

##### 1c-iv. Confirm / Cancel Row

Fixed to the bottom of the page (sticky footer inside the page container, not a browser-level fixed position):

```
className="flex gap-3 pt-6 border-t border-border mt-8"
```

```
[ Cancel ]                               ← Button variant="outline" size="default"
                                            Resets to UPLOAD state (no confirmation dialog)

[ Import Deck ]                          ← Button variant="default" size="default"
                                            disabled when pendingDeckName.trim() === ''
                                            Submits FormData to POST /api/import
```

The "Import Deck" button is the primary CTA for this phase. Label is specific: "Import Deck" (verb + noun, not "Submit" or "Confirm").

**Submission flow:**
1. User clicks "Import Deck".
2. Button enters loading state: `disabled`, content replaced with `Loader2 animate-spin h-4 w-4` + " Importing...".
3. `useImport` sends `FormData` with `file` + `deckName` to `POST /api/import` via `baseFetch` (not `api.post()` — see RESEARCH.md Pitfall 3).
4. On 201: transition to SUCCESS state (§1d).
5. On 4xx/5xx: show error alert (§1e).

---

#### 1d. SUCCESS State — Import Complete

The entire page content is replaced by a centered completion block. Layout: `flex flex-col items-center justify-center text-center py-16 gap-4 max-w-md mx-auto`.

```
[ CheckCircle2 icon ]                    ← lucide-react CheckCircle2, h-12 w-12 text-green-500

[ Deck imported! ]                       ← text-xl font-semibold (Heading role)

[ "{deckName}" was created with {N} cards. ]
                                         ← text-sm text-muted-foreground (Body role)
                                            deckName is the user-edited name submitted

[ View Deck ]                            ← Button variant="default" size="lg" w-full max-w-xs
                                            navigates to /decks/{newDeckId}

[ Import another file ]                  ← Button variant="outline" size="sm" w-full max-w-xs mt-2
                                            resets all state to UPLOAD
```

No auto-redirect. User explicitly navigates via "View Deck" or starts again.

---

#### 1e. Error States

**Inline file rejection error (under drop zone, UPLOAD state):**

Shown when client-side size check fails (D-11) or extension is invalid. Rendered as:
```jsx
<p className="text-sm text-destructive mt-2 text-center">
  {errorMessage}
</p>
```

No Alert component here — inline text is sufficient for a single-line rejection.

**Media validation failure alert (PREVIEW or IMPORTING, from backend 422 response):**

Shown using shadcn `Alert` with destructive styling:
```jsx
<Alert variant="destructive" className="mb-6">
  <AlertCircle className="h-4 w-4" />
  <AlertTitle>Import failed</AlertTitle>
  <AlertDescription>
    The following files in your zip failed validation:
    <ul className="mt-2 space-y-1">
      {errors.map((e, i) => (
        <li key={i} className="text-sm">{e.name}: {e.reason}</li>
      ))}
    </ul>
    Remove or fix these files and re-upload the zip.
  </AlertDescription>
</Alert>
```

Shown above the drop zone in UPLOAD state (page stays at UPLOAD after a backend error). The upload zone remains interactive so the user can re-upload immediately.

**Fatal parse error (D-02 — deck header missing):**

Same `Alert variant="destructive"` as media validation failure, but with a single message body:
```
"No deck header found. Your .kartex file must start with a --- YAML block."
```

**Generic network error:**

```
"Upload failed. Check your connection and try again."
```

## State Machine Summary

| State | Trigger In | Trigger Out | UI |
|-------|-----------|------------|-----|
| `UPLOAD` | Initial / Cancel / Error reset | File selected + size OK → `PARSING` | Drop zone + Browse button |
| `PARSING` | File selected | Parse success → `PREVIEW`; Error → `UPLOAD` (with error shown) | Spinner + Progress bar |
| `PREVIEW` | Parse success | Confirm → `IMPORTING`; Back/Cancel → `UPLOAD` | Deck metadata + Card list + Confirm row |
| `IMPORTING` | Confirm clicked | 201 success → `SUCCESS`; 4xx/5xx → `PREVIEW` (with error shown) | Button loading state |
| `SUCCESS` | 201 from `/api/import` | "View Deck" → `/decks/:id`; "Import another" → `UPLOAD` | Completion block |

Note: `IMPORTING` is not a separate visual page state — it is captured by the disabled + loading button state within `PREVIEW`. The card list and metadata remain visible during submission.
