**Logo SVG color contract (BRAND-01 / BRAND-02):**

The new `logo.svg` must use these specific values so it reads correctly in both light and dark modes when displayed as an `<img>` (SVG is not recolored by CSS — colors are baked in):

| Element | Fill | Rationale |
|---------|------|-----------|
| Card rectangle fill | `#ffffff` (white) | Visible on both light (`--card: white`) and dark (`--card: hsl(0 0% 9%)`) brand area backgrounds; works with white maskable icon background added by generator |
| Card rectangle stroke | `#4f46e5` (indigo-600) | Existing project brand color per RESEARCH.md; visible at all icon sizes |
| "K" lettermark path | `#4f46e5` (indigo-600) | Matches card stroke; high contrast against white card fill |
| SVG canvas | transparent (no `<rect>` background fill) | Transparent lets the `--card` surface show through in header; generator adds white bg for maskable/apple-touch automatically |

**Contrast check:**
- White card (`#ffffff`) on indigo sidebar/card surface (`hsl(0 0% 9%)` ≈ `#171717`): passes WCAG AA (white on near-black)
- Indigo `#4f46e5` on white card: contrast ratio ~4.7:1 — passes WCAG AA for graphical objects (3:1 required)

Source: RESEARCH.md Pattern 2 (Option B recommendation), existing `index.css` CSS variable values.

## SVG Logo Design Contract

This section is the authoritative visual specification for `apps/frontend/public/logo.svg`.

### Canvas

| Property | Value |
|----------|-------|
| viewBox | `0 0 512 512` |
| width / height | `512` / `512` |
| Background | Transparent (no `<rect>` background — generator handles maskable bg) |

### Card Motif

| Property | Value |
|----------|-------|
| Element | `<rect>` |
| Position | `x="96" y="56"` |
| Size | `width="320" height="400"` |
| Corner radius | `rx="32" ry="32"` |
| Fill | `#ffffff` |
| Stroke | `#4f46e5` |
| Stroke-width | `24` (min 24px on 512-grid for legibility at 16px favicon rendering) |

Card stays within inner 410×410px safe zone (96px left margin > 51px minimum; top 56px > 51px minimum). Maskable icon safe zone constraint satisfied.

### "K" Lettermark

| Property | Value |
|----------|-------|
| Element | `<path>` with `d` attribute (outlined vector — **no `<text>` element**) |
| Fill | `#4f46e5` |
| Stroke | none |
| Approximate bounding box | 160×240px, centered in card (x≈176, y≈136 within the 320×400 card) |
| Constraint | All path data must be closed filled shapes; no open strokes |

**Authoring requirement:** The "K" path must be authored in a vector editor (Inkscape: Path → Object to Path; Figma: Flatten). Do NOT use `<text font-family="Arial">K</text>` — `sharp`/librsvg will fail to resolve system fonts in Docker/CI (Pitfall 1, RESEARCH.md).

**Anti-patterns (explicitly forbidden in logo.svg):**
- `<text>` element with `font-family`
- External stylesheet references (`<link>` or `<?xml-stylesheet>`)
- CSS classes that reference Tailwind or external tokens
- Strokes narrower than 12px on the 512 grid (sub-pixel at favicon size)
- Content outside inner 410×410px area (maskable safe zone violation)

Source: RESEARCH.md Pattern 2, Pitfall 1, Pitfall 3. Constraint confirmed by Phase 12 decision record.

## AppShell Brand Area Contract

Two locations in `apps/frontend/src/components/AppShell.tsx` must be updated identically:

### Location 1 — Desktop Sidebar (line 53)

**Before:**
```tsx
<div className="h-16 flex items-center px-4">
  <span className="text-xl font-bold">Kartex</span>
</div>
```

**After:**
```tsx
<div className="h-16 flex items-center gap-2 px-4">
  <img
    src="/logo.svg"
    alt=""
    className="h-8 w-8 shrink-0"
    aria-hidden="true"
  />
  <span className="text-xl font-bold">Kartex</span>
</div>
```

### Location 2 — Mobile Drawer (line 154)

Identical change as Location 1. Both brand divs must match exactly.

**Accessibility rule:** `alt=""` (empty string) + `aria-hidden="true"` — the logo is a decorative brand mark; the adjacent "Kartex" text span is the accessible label. Do NOT use `alt="Kartex"` (would be read twice by screen readers: once for img, once for span).

Source: RESEARCH.md Pattern 1, Pitfall 4. Accessibility: WCAG 2.1 SC 1.1.1 (decorative images use `alt=""`).

## PWA Icon Generation Contract

**Generator command (run from `apps/frontend/` after replacing logo.svg):**
```bash
npx @vite-pwa/assets-generator --preset minimal-2023 public/logo.svg
cp public/apple-touch-icon-180x180.png public/apple-touch-icon.png
```

**Required output files (all 7 must exist after generator run):**

| File | Size | Purpose | Background |
|------|------|---------|------------|
| `public/favicon.ico` | 48×48 | Browser tab fallback | Transparent |
| `public/favicon.svg` | vector | Browser tab (modern) | Transparent |
| `public/pwa-64x64.png` | 64×64 | PWA supplemental | Transparent |
| `public/pwa-192x192.png` | 192×192 | PWA install (any) | Transparent |
| `public/pwa-512x512.png` | 512×512 | PWA splash (any) | Transparent |
| `public/maskable-icon-512x512.png` | 512×512 | Android home screen | White (added by generator) |

**Critical:** `apple-touch-icon.png` is NOT generated by the CLI — it must be copied from `apple-touch-icon-180x180.png` after each generator run. (Phase 12 decision `12-01`, confirmed pitfall.)
