## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → POST /api/decks/:id/update/preview | Untrusted multipart body: file content + deckId from URL |
| browser → POST /api/decks/:id/update/apply | Untrusted multipart body: file content + keepRemoved string + deckId from URL |
| JWT cookie → userId | Trusted after authMiddleware validates JWT signature |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Elevation of Privilege | POST /:id/update/preview | mitigate | `deck.ownerId !== userId → 403` checked before any DB write — per ASVS V4 |
| T-16-02 | Elevation of Privilege | POST /:id/update/apply | mitigate | Same owner gate in apply handler; re-computed on every request (stateless) |
| T-16-03 | DoS | bodyLimit middleware | mitigate | `bodyLimit({ maxSize: MAX_BYTES })` as FIRST argument in handler chain before `async (c) =>` — per RESEARCH.md Pitfall 1 |
| T-16-04 | Tampering | parseKartex input | mitigate | `parseKartex` returns `KartexParseError` on fatal; duplicate kartexId guard returns 422 before DB write |
| T-16-05 | Tampering | tx.card.update in apply | mitigate | Update payload contains only `frontContent`, `backContent`, `tags` — `CardProgress` fields never referenced; `kartexId` never updated (match key) |
| T-16-06 | Tampering | keepRemoved flag | mitigate | `keepRemoved` only controls deletion of caller's own deck cards; owner check precedes transaction — no cross-user deletion possible |
| T-16-07 | Spoofing | userId source | mitigate | `userId = c.get('userId')` — sourced from JWT only, never from request body (T-16-12) |
| T-16-SC | Tampering | npm/pip/cargo installs | accept | No new packages in this phase |
</threat_model>
