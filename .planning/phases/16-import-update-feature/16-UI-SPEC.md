## Color

All colors are CSS variables resolved from `src/index.css`. Supports light and dark modes.

| Role | CSS Variable | Light Value | Dark Value | Usage |
|------|-------------|-------------|------------|-------|
| Dominant (60%) | `--background` | `hsl(0 0% 98%)` | `hsl(0 0% 4%)` | Modal overlay surface, page background |
| Secondary (30%) | `--card` / `--secondary` | `hsl(0 0% 100%)` / `hsl(0 0% 96%)` | `hsl(0 0% 9%)` / `hsl(0 0% 15%)` | DialogContent surface, diff count chips |
| Accent (10%) | `--primary` | `hsl(0 0% 9%)` | `hsl(0 0% 98%)` | Apply button (primary variant), Switch checked state |
| Destructive | `--destructive` | `hsl(0 84% 60%)` | `hsl(0 62% 30%)` | No destructive actions in modal; keepRemoved=off warning hint text only |
| Muted text | `--muted-foreground` | `hsl(0 0% 45%)` | `hsl(0 0% 64%)` | Loading spinner label, hint text, secondary counts |
| Border | `--border` | `hsl(0 0% 90%)` | `hsl(0 0% 15%)` | Diff chip borders, modal border |

**Accent reserved for:**
- Primary "Apply changes" Button (`variant="default"` = bg-primary)
- Switch thumb fill when keepRemoved is checked (`data-[state=checked]:bg-primary`)

**Accent is NOT used for:**
- Diff count numbers — use `text-foreground`
- "Update from file" button — use `variant="outline"`
- Cancel button — use `variant="outline"`
- Error message text — use `text-destructive-foreground` inside destructive-colored container or plain `text-foreground`

## Interaction States

### DeckUpdateModal state machine

| State | Trigger | Visual |
|-------|---------|--------|
| `uploading` | Modal opens with file set | Centered Loader2 spinner + "Uploading..." label; no footer buttons |
| `previewing` | Preview fetch succeeds | Diff grid + Switch row; Cancel + Apply footer |
| `applying` | User clicks Apply | Loader2 spinner + "Applying..." label; Apply button disabled (`aria-busy="true"`) |
| `done` | Apply fetch succeeds | toast.success fires; onSuccess() called; modal closes |
| `error` | Any fetch fails | Error title + body text; Close button only |

The modal does NOT render a "cancel" or "close" affordance in the `uploading` state — the user must wait for the preview response. The standard Dialog X button (top-right) remains available for keyboard/escape dismissal in all states.

### "Update from file" button (DeckDetailPage)

| Interaction | Visual |
|-------------|--------|
| Default | `Button size="sm" variant="outline"` — matches "Edit deck" button beside it |
| After click | File picker opens (OS native); button has no loading state |
| File selected | DeckUpdateModal opens with `open=true`, `file=selectedFile` |

## Copywriting Contract

All strings are i18n keys. English values are the canonical copy. See RESEARCH.md §i18n Keys for German translations.

| Element | i18n Key | English Copy |
|---------|----------|--------------|
| Trigger button | `deckUpdate.updateFromFile` | "Update from file" |
| Modal title | `deckUpdate.modalTitle` | "Update Deck from File" |
| Uploading label | `deckUpdate.uploading` | "Uploading..." |
| Preview section heading | `deckUpdate.previewHeading` | "Changes preview" |
| Diff chip — added | `deckUpdate.added` | "{{count}} added" |
| Diff chip — updated | `deckUpdate.updated` | "{{count}} updated" |
| Diff chip — unchanged | `deckUpdate.unchanged` | "{{count}} unchanged" |
| Diff chip — removed | `deckUpdate.removed` | "{{count}} removed" |
| Switch label | `deckUpdate.keepRemovedLabel` | "Keep removed cards" |
| Switch hint | `deckUpdate.keepRemovedHint` | "When off, cards absent from the file will be deleted." |
| Apply CTA | `deckUpdate.apply` | "Apply changes" |
| Applying label | `deckUpdate.applying` | "Applying..." |
| Success toast | `deckUpdate.successToast` | "Deck updated successfully" |
| Error title | `deckUpdate.errorTitle` | "Update failed" |
| Error — parse fail | `deckUpdate.parseError` | "Could not parse the file. Check it is a valid .kartex file." |
| Error — file too large | `deckUpdate.fileTooLarge` | "File is too large." |

**Primary CTA:** "Apply changes" — verb + noun, confirms the destructive-adjacent operation.

**Empty state:** Not applicable to this phase. The modal always has content (either diff or error).

**Error states:**
- Parse error: "Could not parse the file. Check it is a valid .kartex file." — names the problem and the action.
- File too large: "File is too large." — concise; no action needed (user must choose a smaller file).
- Network/server error: `deckUpdate.errorTitle` + server message if available, else `deckUpdate.parseError` as fallback.

**Destructive action handling — "Keep removed cards" toggle:**

The toggle is NOT a destructive confirmation. When turned off, the diff chip for "removed" provides visual feedback of what will be deleted. No separate confirm dialog is required — the "Apply changes" button serves as the single confirmation point. The hint text (`deckUpdate.keepRemovedHint`) is the user's warning.

No inline "are you sure?" prompt is required because:
1. The diff count shows exactly how many cards will be removed.
2. The Apply button is the explicit commit action.
3. SM-2 CardProgress is preserved (IMP-03) — the operation is partially recoverable (user can re-import to restore content).

## Accessibility Contract

| Element | ARIA / Behavior |
|---------|----------------|
| Dialog | `role="dialog"`, `aria-modal="true"` — provided by Radix UI DialogPrimitive |
| DialogTitle | Required — Radix requires title for `aria-labelledby` |
| Diff grid chips | `role="region"` with `aria-label={t('deckUpdate.added')}` etc. — matches StatsSummaryPanel chip pattern |
| Switch row | `<label>` wraps Switch + text OR use `htmlFor` with matching `id` on Switch — do NOT rely on proximity alone |
| Loading states | `aria-busy="true"` on container; Loader2 has `aria-hidden="true"` (decorative icon) |
| Apply button (applying) | `disabled` + `aria-busy="true"` |
| File input | `className="sr-only"` + `aria-hidden="true"` — visually hidden; triggered by Button click only |
| Error state | Wrap error text in `role="alert"` so screen readers announce it immediately |
